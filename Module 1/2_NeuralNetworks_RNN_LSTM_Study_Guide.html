Section 01

Foundations: Neuron, Layer, Network

Deep learning is machine learning with multiple learnable layers of representation. The defining shift is that features are no longer hand-designed — the network learns the features and the prediction rule together, from the same loss signal.

Classical ML
  • Human designs features (SIFT, TF-IDF, hand-crafted ratios)
  • Model learns only the final mapping
  • Feature engineering is where the effort goes
  • Works well when data is small and structured
Deep Learning
  • Raw input goes straight in
  • Model learns features AND mapping jointly
  • Architecture design is where the effort goes
  • Needs more data and compute, scales better

The single neuron

FIG 1 — A single neuron. Two operations: a weighted sum (linear) followed by an activation (non-linear). Everything in deep learning is built from repeating this.

Layer form (vectorized)

// Single sample z = W·x + b // W ∈ ℝ^(d_out × d_in), x ∈ ℝ^d_in, b ∈ ℝ^d_out a = g(z) // elementwise activation // Batch of N samples (how it's actually implemented) Z = X·Wᵀ + b // X ∈ ℝ^(N × d_in) → Z ∈ ℝ^(N × d_out) A = g(Z) // Full L-layer network a⁰ = x aˡ = g(Wˡ·aˡ⁻¹ + bˡ) for l = 1 … L ŷ = aᴸ
Why non-linearity is mandatory: Stack two linear layers and you get W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂), which is just another linear layer with weights W′ = W₂W₁. Without g(·), a 100-layer network has exactly the representational power of a 1-layer network. The activation is what buys you depth.

Section 02

Activation Functions

The choice of activation determines what gradients look like during training. The derivative matters more than the function itself, because that's what flows backward.

FIG 2 — The four activations and their derivatives (dashed). The derivative curve is what determines whether gradients survive a deep stack.
Activation Formula Derivative Range Used where
Sigmoid σ(z) = 1/(1+e⁻ᶻ) σ(z)·(1−σ(z)) (0, 1) Binary output, LSTM/GRU gates
Tanh tanh(z) 1 − tanh²(z) (−1, 1) RNN hidden state, LSTM candidate
ReLU max(0, z) 1 if z>0, else 0 [0, ∞) MLP / CNN hidden layers
Leaky ReLU max(0.01z, z) 1 if z>0, else 0.01 (−∞, ∞) Fixes "dying ReLU" neurons
GELU z · Φ(z) smooth ≈(−0.17, ∞) Transformers (BERT, GPT)
Softmax eᶻⁱ / Σⱼ eᶻʲ see note below (0,1), sums to 1 Multi-class output layer
Choosing in practice: ReLU for hidden layers in feed-forward and convolutional nets. Tanh for recurrent hidden states (zero-centred keeps the state from drifting). Sigmoid only for gates and binary outputs — never as a deep hidden activation. GELU if you're building a Transformer.
Dying ReLU: If a neuron's pre-activation goes strongly negative for all inputs, ReLU outputs 0, its gradient is 0, and it never recovers — the neuron is permanently dead. Leaky ReLU and careful initialization prevent this.

Forward Propagation — Complete Numerical Walkthrough

We'll use a 2-input, 3-hidden, 2-output network. It's small enough to compute by hand but large enough to show hidden-layer backpropagation properly (each hidden node feeds both outputs, which is where the interesting chain rule appears).

FIG 3 — The 2-3-2 network with all forward-pass values filled in. Weights w₁–w₆ connect input→hidden; w₇–w₁₂ connect hidden→output.

Step 1 — Hidden layer pre-activations and activations

// z = w·i, then a = sigmoid(z) = 1/(1+e^-z) z_h1 = w₁·i₁ + w₄·i₂ = 0.1(0.85) + 0.4(0.25) = 0.085 + 0.100 = 0.185 a_h1 = σ(0.185) = 1/(1 + e^-0.185) = 0.5461 z_h2 = w₂·i₁ + w₅·i₂ = 0.2(0.85) + 0.5(0.25) = 0.170 + 0.125 = 0.295 a_h2 = σ(0.295) = 0.5732 z_h3 = w₃·i₁ + w₆·i₂ = 0.3(0.85) + 0.6(0.25) = 0.255 + 0.150 = 0.405 a_h3 = σ(0.405) = 0.5999

Section 04

Loss Functions

The loss converts "how wrong is the prediction" into a single scalar that can be differentiated. Choosing the wrong loss for the task is one of the most common practical mistakes.

Our example — squared error with ½ factor

E_total = ½ · [ (target₁ − a_o1)² + (target₂ − a_o2)² ] = ½ · [ (1 − 0.5924)² + (0 − 0.6520)² ] = ½ · [ (−0.4076)² + (0.6520)² ] = ½ · [ 0.16614 + 0.42510 ] = ½ · 0.59124 = 0.29562 // Why the ½ factor? // d/da [½(t−a)²] = −(t−a) = (a−t) // The 2 from the power rule cancels the ½ — the derivative comes out clean. // It has no effect on where the minimum is, only on the constant.
Loss Formula Derivative w.r.t. prediction Use for
Mean Squared Error ½(y − ŷ)² ŷ − y Regression, continuous targets
Mean Absolute Error |y − ŷ| sign(ŷ − y) Regression robust to outliers
Binary Cross-Entropy −[y·log ŷ + (1−y)·log(1−ŷ)] (ŷ − y)/(ŷ(1−ŷ)) Binary classification
Categorical Cross-Entropy −Σᵢ yᵢ · log ŷᵢ ŷ − y (with softmax) Multi-class classification
Huber MSE near 0, MAE far away piecewise Regression with some outliers
The softmax + cross-entropy shortcut: When categorical cross-entropy follows a softmax layer, the combined derivative simplifies to exactly ŷ − y. All the messy softmax Jacobian terms cancel. This is why the two are almost always paired — the gradient is both simple and numerically stable.
Why not MSE for classification? MSE with a sigmoid output produces a gradient containing σ′(z), which is tiny when the model is confidently wrong — exactly when you most want a large correction. Cross-entropy's gradient does not have this term, so wrong-and-confident predictions get corrected fast.
Section 05

Backpropagation — Full Derivation

Backpropagation is the chain rule applied systematically, computing gradients from the output backward so that shared sub-expressions are calculated once and reused.

FIG 4 — The chain rule made concrete. Each box is a local derivative computed independently; the product is the gradient for w₇.

Step 1 — Output layer deltas

A delta (δ) is the error signal at a node — it bundles the first two chain-rule terms so they don't have to be recomputed for every incoming weight.

// δ_o = (a_o − target) · a_o(1 − a_o) // └── loss deriv ──┘ └─ sigmoid deriv ─┘ δ_o1 = (0.5924 − 1.0) · 0.5924 · (1 − 0.5924) = (−0.4076) · 0.5924 · 0.4076 = (−0.4076) · 0.24146 = −0.09843 δ_o2 = (0.6520 − 0.0) · 0.6520 · (1 − 0.6520) = (0.6520) · 0.6520 · 0.3480 = (0.6520) · 0.22690 = +0.14793

Step 2 — Output layer weight gradients & updates

// Gradient for any hidden→output weight: ∂E/∂w = δ_o · a_h // Update rule: w_new = w_old − α·gradient, with α = 0.1 ∂E/∂w₇ = δ_o1 · a_h1 = (−0.09843)(0.5461) = −0.05375 w₇_new = 0.25 − 0.1(−0.05375) = 0.25538
Weight Connects δ used a used Gradient Updated value
w₇ h₁ → o₁ δ_o1 a_h1 −0.05375 0.25538
w₉ h₂ → o₁ δ_o1 a_h2 −0.05642 0.10564
w₁₁ h₃ → o₁ δ_o1 a_h3 −0.05904 0.30590
w₈ h₁ → o₂ δ_o2 a_h1 +0.08079 0.49192
w₁₀ h₂ → o₂ δ_o2 a_h2 +0.08480 0.19152
w₁₂ h₃ → o₂ δ_o2 a_h3 +0.08874 0.39113
Read the signs: o₁ was too low (0.59 vs target 1.0), so its gradients are negative and the update increases those weights. o₂ was too high (0.65 vs target 0.0), so its gradients are positive and the update decreases those weights. The arithmetic is doing exactly what intuition says it should.

Step 3 — Hidden layer deltas (the interesting part)

Each hidden neuron influences both outputs, so its error signal must be summed over all downstream paths. This is the part that separates real backpropagation from a single-path chain rule.

// Downstream error reaching h₁ (sum over BOTH output paths) ∂E_total/∂a_h1 = δ_o1·w₇ + δ_o2·w₈ = (−0.09843)(0.25) + (0.14793)(0.5) = −0.02461 + 0.07397 = 0.04936 // Multiply by the local sigmoid derivative to get δ_h1 δ_h1 = 0.04936 · a_h1(1 − a_h1) = 0.04936 · 0.5461 · 0.4539 = 0.04936 · 0.24788 = 0.012235 // Same procedure for h₂ and h₃ δ_h2 = (δ_o1·w₉ + δ_o2·w₁₀) · a_h2(1−a_h2) = 0.004830 δ_h3 = (δ_o1·w₁₁ + δ_o2·w₁₂) · a_h3(1−a_h3) = 0.007116

Notice the magnitudes: the input-layer gradients (~0.001–0.01) are roughly ten times smaller than the output-layer gradients (~0.05–0.09). In a two-layer network that's harmless. Repeat this shrinkage across twenty layers and the early layers effectively stop learning — this is the vanishing gradient problem, visible right here in a hand calculation.

The general backpropagation algorithm

// For each training example: 1. FORWARD: for l = 1…L: zˡ = Wˡaˡ⁻¹ + bˡ ; aˡ = g(zˡ) 2. LOSS: E = Loss(aᴸ, y) 3. OUTPUT δ: δᴸ = ∇ₐE ⊙ g′(zᴸ) 4. BACKWARD: for l = L−1…1: δˡ = ((Wˡ⁺¹)ᵀ δˡ⁺¹) ⊙ g′(zˡ) 5. GRADIENTS: ∂E/∂Wˡ = δˡ (aˡ⁻¹)ᵀ and ∂E/∂bˡ = δˡ 6. UPDATE: Wˡ ← Wˡ − α·∂E/∂Wˡ // ⊙ = elementwise (Hadamard) product
Section 06

Gradient Descent & Optimization

Gradients tell you which direction reduces the loss. The optimizer decides how big a step to take and whether to use history from previous steps.

The three descent variants

Variant Samples per update Pros Cons
Batch GD Entire dataset Stable, smooth convergence Very slow; whole dataset must fit in memory
Stochastic GD 1 sample Fast updates; noise can escape local minima Noisy path; poor hardware utilization
Mini-batch GD 32 – 512 Best of both; GPU-efficient Batch size becomes a hyperparameter
// Vanilla SGD w ← w − α · ∂E/∂w // SGD with momentum — accumulates a velocity term v ← β·v + (1−β)·∂E/∂w // β ≈ 0.9 w ← w − α·v // RMSProp — scales the step by recent gradient magnitude s ← β·s + (1−β)·(∂E/∂w)² w ← w − α·∂E/∂w / (√s + ε) // Adam — momentum + RMSProp, with bias correction v ← β₁·v + (1−β₁)·g // β₁ = 0.9 s ← β₂·s + (1−β₂)·g² // β₂ = 0.999 v̂ = v/(1−β₁ᵗ) , ŝ = s/(1−β₂ᵗ) // bias correction w ← w − α·v̂/(√ŝ + ε) // ε = 1e-8

Learning rate — the single most important hyperparameter

↑

Too large

Loss oscillates or diverges to NaN. The step overshoots the minimum every time.

↓

Too small

Training crawls; may stall in a flat region and never reach a good minimum.

✓

Good starting points

Adam: 1e-3. SGD: 1e-2. Transformers: 1e-4 with warmup.

~

Scheduling

Decay over training — step, cosine, or warmup-then-decay for Transformers.

Scheme Variance Pair with

Xavier / Glorot 2 / (d_in + d_out) Sigmoid, tanh

Section 07

Neural Network Families

Every architecture family exists because it exploits a different structural assumption about the data. Choosing an architecture is mostly about matching that assumption to your data's shape and dependency pattern.

FIG 5 — The five families and the structural assumption each one encodes. Start by asking what shape the data is, not which model is fashionable.
# Family Structural assumption Use when Avoid when
1 MLP / Feed-forward Features are independent; no spatial or temporal structure Tabular data, risk scores, encoded metadata, small feature sets Raw data has strong spatial or sequential structure
2 CNN Local patterns are meaningful and repeat across positions (translation invariance) Images, spectrograms, screenshots, spatial maps Data has no locality — shuffling columns wouldn't matter
3 Autoencoder Data lies on a lower-dimensional manifold Compression, denoising, anomaly detection, representation learning You need discriminative prediction, not reconstruction
4 Encoder–Decoder Input and output are both sequences, possibly of different lengths Translation, summarization, code generation Output is a single label — just use an encoder
5 RNN Order matters; recent context is most relevant Short/medium sequences where model size must stay small Long sequences (vanishing gradients) or when parallelism is needed
6 LSTM / GRU Order matters and long-term memory must persist Sequence memory matters but Transformer cost isn't justified Very long context, or when you have data and compute for a Transformer
7 Transformer Any token may depend on any other, at any distance Language, long-range dependency, large-scale pretraining, multimodal Data or compute is small — a simpler model will generalize better

Practical decision table

Situation Start with Reason
Small tabular dataset Logistic regression, tree, or small MLP Simple models often generalize better on limited data
Large tabular with nonlinear interactions MLP or gradient boosting Both learn feature interactions; boosting is often stronger on tabular
Images or visual layout CNN, or Vision Transformer if data is large CNN encodes locality efficiently and needs less data
Compression or anomaly detection Autoencoder Reconstruction error flags unusual samples
Short ordered sequence RNN or GRU Small recurrent model is efficient and sufficient
Longer sequence needing memory LSTM or GRU Gates preserve information across many timesteps
Sequence in → sequence out Encoder–decoder Separates reading from generating
Text generation / LLM Decoder-only Transformer Masked self-attention matches next-token prediction
Text understanding / embeddings Encoder-only Transformer Bidirectional context gives richer representations
Section 08

Autoencoders

An autoencoder learns to reconstruct its own input through a narrow bottleneck. Because the bottleneck can't carry everything, the network is forced to keep only what matters — which is exactly what a good representation is.

FIG 6 — Autoencoder structure. The bottleneck forces compression; the reconstruction error is both the training signal and, at inference, an anomaly score.
// Encoder compresses, decoder reconstructs z = f_encoder(x) // dim(z) << dim(x) x̂ = f_decoder(z) // Training objective — reconstruct your own input L = ‖x − x̂‖² // or binary cross-entropy for [0,1] data
Variant Modification Purpose
Undercomplete AE dim(z) < dim(x) Standard compression / dimensionality reduction
Denoising AE Corrupt the input, reconstruct the clean original Learns robust features; prevents identity shortcut
Sparse AE L1 penalty on latent activations Forces interpretable, sparse codes
Variational AE (VAE) z is a distribution; adds a KL divergence term Generative — you can sample new data from the latent space
Why the bottleneck matters: if dim(z) ≥ dim(x), the network can simply learn the identity function and achieve zero loss while learning nothing useful. The constraint is the learning signal.
Section 09

Encoder–Decoder (Seq2Seq)

Encoder–decoder is a design pattern, not a specific architecture. It can be built from RNNs, LSTMs, GRUs, CNNs, or Transformers. The idea: one network reads the whole input into a representation, a second network generates the output from it.

FIG 7 — Basic Seq2Seq. Everything the decoder knows about the source passes through a single context vector — the bottleneck that attention was invented to remove.
// Encoder reads the full input sequence c = Encoder(x₁, x₂, …, x_Tx) // usually c = h_Tx, the final hidden state // Decoder generates one token at a time, conditioned on c s_t = Decoder(s_{t-1}, y_{t-1}, c) y_t = softmax(W·s_t + b) // Training loss over the whole target sequence L = − Σ_t log P(y_t* | y*_<t, x)

Teacher forcing

During training
  • Feed the true previous token y*ₜ₋₁
  • Converges much faster and more stably
  • All timesteps can be computed in parallel
During inference
  • Feed the model's own previous prediction
  • Errors compound — called exposure bias
  • Mitigated by scheduled sampling or beam search
Section 10

RNN and Backpropagation Through Time

A recurrent neural network processes a sequence one timestep at a time, carrying a hidden state that acts as memory. Critically, the same weights are reused at every timestep — this is weight sharing across time, exactly analogous to a CNN's weight sharing across space.

FIG 8 — The same RNN cell drawn folded (left) and unrolled across four timesteps (right). Unrolling is what makes backpropagation possible — but also what creates the long multiplication chain.
// RNN forward equations h_t = tanh( W_xh·x_t + W_hh·h_{t-1} + b_h ) y_t = W_hy·h_t + b_y // Symbols // x_t input at timestep t // h_t hidden state (memory) at timestep t // W_xh input → hidden weights (h × d) // W_hh hidden → hidden (recurrent) (h × h) // W_hy hidden → output weights (o × h)

Numerical example — one RNN timestep

// Given: x_t = 0.7, h_{t-1} = 0.4, W_xh = 0.8, W_hh = 0.5, b = 0.1 z_t = W_xh·x_t + W_hh·h_{t-1} + b = 0.8(0.7) + 0.5(0.4) + 0.1 = 0.56 + 0.20 + 0.10 = 0.86 h_t = tanh(0.86) = 0.696 // This new h_t becomes h_{t-1} for the next timestep.

Backpropagation Through Time

// Total loss is summed over all timesteps L = L₁ + L₂ + … + L_T // The recurrent weight receives gradient from EVERY timestep ∂L/∂W_hh = Σ_t ∂L_t/∂W_hh // Expanding one term reveals the product chain: ∂L_t/∂h_k = (∂L_t/∂h_t) · Π_{j=k+1}^{t} (∂h_j/∂h_{j-1}) = (∂L_t/∂h_t) · Π_{j} ( W_hhᵀ · diag(tanh′(z_j)) ) └─── this product is the problem ───┘

Vanishing and exploding gradients

FIG 9 — The two failure modes of BPTT. Since tanh′ ≤ 1 always, vanishing is by far the more common problem in practice.
Problem Cause Symptom Fix
Vanishing gradient Repeated multiplication by values < 1 Model ignores long-range context; early timesteps don't learn LSTM/GRU, residual paths, attention
Exploding gradient Repeated multiplication by values > 1 Loss spikes then becomes NaN Gradient clipping, lower learning rate

RNN input/output configurations

Type Shape Example task
One-to-many 1 input → sequence out Image captioning
Many-to-one Sequence in → 1 output Sentiment classification
Many-to-many (aligned) Same length in and out POS tagging, NER
Many-to-many (seq2seq) Different lengths Translation, summarization

LSTM — Long Short-Term Memory

LSTM's key innovation is a separate cell state c t that flows through time with only additive updates and elementwise multiplications — no repeated matrix multiplication. This is the "memory highway" that lets gradients travel far without vanishing.

FIG 10 — LSTM cell. The orange highway at the top is the cell state: it passes through only a multiply (forget) and an add (input), which is why gradients survive along it.
// The four gates — all read [h_{t-1}, x_t], all have their own weights f_t = σ( W_f·[h_{t-1}, x_t] + b_f ) // forget: what to erase from memory i_t = σ( W_i·[h_{t-1}, x_t] + b_i ) // input: how much new info to write c̃_t = tanh( W_c·[h_{t-1}, x_t] + b_c ) // candidate: what the new info IS o_t = σ( W_o·[h_{t-1}, x_t] + b_o ) // output: how much memory to expose // The two state updates c_t = f_t ⊙ c_{t-1} + i_t ⊙ c̃_t // cell state — ADDITIVE, no matmul h_t = o_t ⊙ tanh(c_t) // hidden state — filtered view of memory // ⊙ = elementwise product. σ outputs ∈ (0,1) — gates act as soft switches.

Numerical example — one LSTM timestep

// Given: c_{t-1} = 1.20, f_t = 0.75, i_t = 0.40, c̃_t = 0.60, o_t = 0.80 // Step 1 — how much of the old memory survives? f_t ⊙ c_{t-1} = 0.75 × 1.20 = 0.90 // kept 75% of 1.20 // Step 2 — how much new information is written? i_t ⊙ c̃_t = 0.40 × 0.60 = 0.24 // wrote 40% of the candidate // Step 3 — new cell state is the sum c_t = 0.90 + 0.24 = 1.14 // Step 4 — hidden output is a gated, squashed view of the cell tanh(1.14) = 0.8144 h_t = 0.80 × 0.8144 = 0.651
Why this solves vanishing gradients: The cell-state path is c_t = f_t ⊙ c_{t−1} + …. Differentiating gives ∂c_t/∂c_{t−1} = f_t. If the forget gate learns to stay near 1, the gradient passes through almost unchanged across many timesteps. Compare this to the vanilla RNN, where every step multiplies by W_hhᵀ·diag(tanh′) — a term that is essentially always < 1.

Gate intuition with a concrete example

Gate Range Question it answers Example: reading "The cat, which was hungry, ate"
Forget f_t 0 – 1 What should I erase? Near 1 for "cat is the subject" — keep it through the clause
Input i_t 0 – 1 How much should I write? Low during "which was hungry" — it's a side detail
Candidate c̃_t −1 – 1 What content would I write? Encodes the new information available at this step
Output o_t 0 – 1 What should I expose now? High for subject info when reaching "ate" — needed for agreement

Parameter count

// Each of the four gates has a weight matrix of shape (h × (h+d)) plus a bias params = 4 × [ h·(h + d) + h ] // Example: h = 256, d = 100 = 4 × [ 256 × 356 + 256 ] = 4 × [ 91,136 + 256 ] = 4 × 91,392 = 365,568 parameters // A vanilla RNN with the same dimensions: 91,392 — exactly 1/4 as many.
Section 12

GRU — Gated Recurrent Unit

GRU simplifies the LSTM: it merges the forget and input gates into a single update gate, and drops the separate cell state entirely. Three gates instead of four, ~25% fewer parameters, often equal accuracy.

FIG 11 — GRU cell. One state, three gates. The update gate z performs a linear interpolation between keeping the old state and adopting the candidate.
// GRU equations z_t = σ( W_z·[h_{t-1}, x_t] ) // update gate r_t = σ( W_r·[h_{t-1}, x_t] ) // reset gate h̃_t = tanh( W_h·[ r_t ⊙ h_{t-1}, x_t ] ) // candidate, with reset applied h_t = (1 − z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t // Note the coupling: (1−z) and z must sum to 1. // In an LSTM, f_t and i_t are independent — LSTM can keep old AND add new; // GRU must trade one against the other. That's the expressiveness difference.

Numerical example — one GRU timestep

// Given: h_{t-1} = 0.50, z_t = 0.30, h̃_t = 0.90 h_t = (1 − 0.30) × 0.50 + 0.30 × 0.90 = 0.70 × 0.50 + 0.27 = 0.35 + 0.27 = 0.62 // z = 0.30 means "keep 70% of the old state, take 30% of the new candidate" // z → 0 means ignore the new input entirely (perfect memory) // z → 1 means overwrite completely (no memory)

Head-to-head comparison

Vanilla RNN LSTM GRU
Gates 0 4 (f, i, c̃, o) 3 (z, r, h̃)
States carried h only h and c h only
Params (h hidden, d input) h(h+d)+h 4·[h(h+d)+h] 3·[h(h+d)+h]
Relative cost 1× 4× 3×
Long-range memory Poor Best Good
Training speed Fastest Slowest Middle
Best for Very short sequences Long sequences, large data Small/medium data, faster iteration
Which to pick: Empirically the two are close on most tasks. Start with GRU — it trains faster and has fewer parameters to overfit. Switch to LSTM if you have a lot of data and long dependencies, where the independent forget/input gates give real extra capacity.

Training vs inference memory: Training requires storing every intermediate activation for the backward pass. For an RNN over T timesteps, that's O(T·h) held in memory simultaneously. Inference only needs the current timestep. This is why you can run a model at inference on hardware that couldn't train it.

Common exam questions

Question Answer
Why do we need non-linear activations? Without them, stacked linear layers collapse to a single linear transformation — depth buys nothing
Why the ½ in the squared-error loss? The 2 from differentiating the square cancels it, giving the clean derivative (a − target)
Why does a hidden delta sum over multiple terms? Each hidden neuron influences every downstream neuron, so its error contribution comes from all those paths
What causes vanishing gradients? Repeated multiplication by values < 1 during backprop — sigmoid's derivative caps at 0.25, and W_hh compounds across timesteps
How does LSTM fix vanishing gradients? The cell state updates additively (c_t = f⊙c_{t−1} + …), so ∂c_t/∂c_{t−1} = f_t — near 1 when the gate stays open
How many gates in LSTM vs GRU? LSTM has 4 (forget, input, candidate, output); GRU has 3 (update, reset, candidate)
What is the LSTM parameter count? 4·[h(h+d) + h] — four times the vanilla RNN
What is teacher forcing? Feeding the true previous token during training instead of the model's own prediction — faster convergence, but causes exposure bias at inference
Why can't Seq2Seq handle long sentences? The entire source is compressed into one fixed-size context vector, so information is lost before decoding begins
How do you fix exploding gradients? Gradient clipping — cap the gradient norm at a threshold (typically 1.0)
Why never initialize weights to zero? All neurons in a layer compute identically and receive identical gradients — symmetry never breaks, so the layer behaves like one neuron

Key takeaways

✓

Depth needs non-linearity

The activation function is the only reason stacking layers adds power.

✓

Backprop is the chain rule

Deltas exist so shared sub-expressions are computed once, not per weight.

✓

Match architecture to data shape

Vector → MLP. Grid → CNN. Sequence → RNN family. Any-to-any → Transformer.

✓

Gradients multiply

Which is why depth and sequence length both cause vanishing or exploding gradients.

✓

Gates are learned switches

Sigmoid outputs in (0,1) let the network decide what to keep, write, and expose.

✓

Additive memory survives

LSTM's cell state adds rather than multiplies — that is the whole trick.

✓

Enc–dec is a pattern

Not an architecture. Build it from RNNs, LSTMs, or Transformers as needed.

✓

The bottleneck leads to Part 2

One fixed context vector can't hold a long sentence — attention is the answer.
