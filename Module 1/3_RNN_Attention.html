Section 01

The Problem Attention Solves

Classic Seq2Seq compresses the whole source sentence into one fixed vector. The decoder then generates every output word from that single vector. For long sentences, information is lost before decoding even starts.

FIG 1 — Left: one vector must carry everything. Right: all encoder states are kept, and the decoder builds a new summary at each output step.
One-line summary: Attention lets the decoder build a fresh, custom summary of the source before generating each output word — instead of reusing one frozen summary for the whole sentence.
Section 02

First: What Exactly Is H?

Before any attention math makes sense, you need to be completely solid on what H is. Almost all confusion starts here.

H is a stack of vectors — one per source word. If your sentence has 4 words, H has 4 rows. Each row hᵢ is a vector describing word i in the context of the whole sentence. H is produced once by the encoder, then never changes while the decoder runs.
FIG 2 — H made concrete. Four source words → four rows. Each row is a 512-number vector. The highlighted row h₃ is what "India" looks like to the model.

The complete symbol glossary — read this once, refer back often

Symbol Say it as What it is Shape Changes when?
x_i "x sub i" The i-th source word — Fixed input
h_i "h sub i" Vector for source word i, aware of full sentence context 512 numbers Once, by encoder
H "big H" All the h_i stacked into a matrix 4 × 512 Once, by encoder
T_x "T sub x" Number of source words (= 4 here) a number Per sentence
s_{t−1} "s sub t minus 1" Decoder's state before producing word t. "What I've said so far" 512 numbers Every decoder step
e_{t,i} "e sub t comma i" Raw relevance score of source word i for output step t one number Every decoder step
α_{t,i} "alpha sub t comma i" Attention weight — how much focus word i gets at step t one number, 0–1 Every decoder step
c_t "c sub t" Context vector — the custom source summary for step t 512 numbers Every decoder step
y_t "y sub t" The output word produced at step t — Every decoder step
Read the last column. H and its rows h_i are computed once and stay fixed. Everything with a t in it — s, e, α, c — is recomputed from scratch for every single output word. That difference is the entire mechanism.
Section 03

Destination First: What Are We Actually Building?

Instead of starting with formulas, start with the finish line. The decoder is about to generate one word. Before it can, it needs one thing:

// THE GOAL — this is the only thing attention produces c_t = α₁·h₁ + α₂·h₂ + α₃·h₃ + α₄·h₄ // In words: "a blend of the source word vectors, // where the α values decide the recipe."

That's it. c_t is a weighted average of the source word vectors. If α₃ = 0.6, then 60% of the blend comes from "India". Nothing more mysterious than that.

The smoothie analogy. H is your fruit — four fruits sitting on the counter, always available. The α values are the recipe: how much of each fruit goes in. c_t is the smoothie you actually drink. Different output word → different recipe → different smoothie. The fruit never changes; only the proportions do.

Now unwrap it backwards

To get c_t, we need α. To get α, we need e. To get e, we need s_{t−1} and H. That chain — read right to left — is the whole algorithm.

FIG 3 — Red arrows show the dependency chain (top-down: what needs what). The green dashed arrow shows the order you actually compute in (bottom-up). Understanding runs one way; computation runs the other.
Why this ordering helps: textbooks present e → α → c because that's the computation order. But you can't understand why we'd want e until you know it's serving α, which is serving c. Learn it top-down, then compute it bottom-up.
Section 04

The Word "Weight" Means Two Different Things

This is, in my experience, the single biggest source of confusion in attention. The word "weight" appears everywhere and refers to two completely unrelated objects.

training by gradient descent Frozen once training finishes Same values for every sentence, every step Matrices — thousands of numbers THEIR JOB Define how to score relevance TYPE 2 · ATTENTION WEIGHTS α₁ , α₂ , α₃ , α₄ Computed fresh at every decoder step Never stored or learned Different for every sentence AND every step Just T_x numbers, each 0–1, summing to 1 THEIR JOB Say where to look right now
FIG 4 — Two unrelated things both called "weights". W_a is a fixed rulebook learned once. α is a fresh decision made every single step.
The distinction in one sentence: W_a, U_a, v_a are the learned rules for judging relevance — like a trained recruiter's instincts. α is this specific judgement, right now — like the score that recruiter gives one particular candidate today. The instincts are permanent; the score changes with every candidate.
Consequence worth noticing: because α is never stored, attention adds almost nothing to the model's parameter count. The alignment network W_a/U_a/v_a is small. Yet those few parameters generate a completely different focus pattern for every word of every sentence.
Section 05

The Four Steps, Slowly

We're at decoder step t = 2. The decoder has already said "J'aime" and now needs to produce the next French word. We expect it should be looking at "India".

Setup: Source = "I love India <eos>", so T_x = 4 and H has 4 rows. The decoder's current state s_{t−1} encodes "I have said J'aime; I need an object next."

Score each source word against the decoder's current need

Compare s_{t−1} with each h_i, one at a time. Four comparisons → four numbers. These are the raw scores e. Bigger means "more relevant right now". They can be negative; they're unbounded.

Turn the scores into a recipe with softmax

Raw scores can't be a recipe — they might be −3 or +47. Softmax squashes them so every value lands between 0 and 1 and they all sum to exactly 1. Now they're proportions.

Blend the h vectors using that recipe

Multiply each h_i by its α_i and add them all up. Result: c_t, one vector, same size as a single h. This is the custom source summary for this exact moment.

Hand c_t to the decoder and generate the word

The decoder combines its own state with c_t, updates to s_t, and produces the output word. Then t increases and we return to step 1 with a new s, which will produce new α values.

Step 1 in detail — where do the scores come from?

We need a function that takes (decoder state, one source vector) and returns a single number saying "how relevant". Bahdanau's answer is a tiny neural network:

e_{t,i} = v_aᵀ · tanh( W_a·s_{t−1} + U_a·h_i + b_a )

Read that right to left as a sequence of three simple moves:

FIG 5 — Scoring one (state, source-word) pair. Three moves: project both into a shared space, merge them, collapse to a single number. Repeat for every source word.
Piece Shape Plain-English job
W_a 256 × 512 Reshapes the decoder state into the comparison space
U_a 256 × 512 Reshapes a source vector into the same comparison space
b_a 256 Bias — lets the network shift its baseline
tanh — Non-linearity; lets the model learn complex compatibility, not just a linear match
v_a 256 Collapses the 256-number compatibility vector into one score
Why is it called "additive" attention? Because of the + in Move B — the two projected vectors are added before tanh. Luong's alternative multiplies them instead (a dot product), which is why his is called multiplicative attention. That single operator is the entire difference between the two families.

Step 2 in detail — why softmax and not just "divide by the total"?

// Our four raw scores e₁ = 1.2 e₂ = 0.4 e₃ = 2.1 e₄ = −0.3 ↑ negative! // Naive approach: divide each by the sum. Sum = 3.4 α₄ = −0.3 / 3.4 = −0.088 ✗ a negative proportion is meaningless // Softmax first exponentiates, which forces everything positive exp(1.2) = 3.320 exp(0.4) = 1.492 exp(2.1) = 8.166 exp(−0.3) = 0.741 ← still positive! sum = 3.320 + 1.492 + 8.166 + 0.741 = 13.719 // Now divide — all values are valid proportions α₁ = 3.320 / 13.719 = 0.246 α₂ = 1.492 / 13.719 = 0.109 α₃ = 8.166 / 13.719 = 0.595 ← "India" wins α₄ = 0.741 / 13.719 = 0.054 ───────────── sum = 1.000 ✓
Softmax does two jobs at once: (1) exponentiating makes every value positive, so negative scores are handled gracefully; (2) dividing by the sum makes them add to 1, so they're valid proportions. It also amplifies differences — e₃ was only 1.75× e₁ as a raw score, but α₃ ends up 2.4× α₁. Softmax makes the winner win more decisively.

Step 3 in detail — the actual blending

FIG 6 — The blend done arithmetically. Scale each h by its α, then add column-wise. Real vectors have 512 dimensions; the logic is identical for all of them.
The most important shape fact: c_t has the same dimension as a single h_i (512 here), not the sum of all of them. You are averaging four vectors, not concatenating them. That's why c_t can slot straight into the decoder wherever a source representation is expected.
Section 06

Watch the Loop Run — Three Decoder Steps

Everything above was one step. Here's what makes attention powerful: the same H, scored against three different decoder states, produces three completely different recipes.

FIG 7 — Three decoder steps. H never changes. The decoder state does — and that alone shifts the attention from "I", to "India", to "<eos>".
This is the payoff. Notice how the focus moves: step 1 looks at the start of the sentence, step 2 jumps to the middle, step 3 lands on the end. A fixed context vector physically cannot do this — it's the same vector at every step. Attention is what makes the focus mobile.

The loop written as pseudocode

// ONCE, before decoding starts H = encoder(source_sentence) // shape (T_x, 512) — then frozen s = initial_state // THEN, repeat for each output word while not done: // STEP 1 — score every source word against current state for i in 1…T_x: e[i] = v_aᵀ · tanh(W_a·s + U_a·H[i] + b_a) // STEP 2 — normalize into a recipe α = softmax(e) // T_x numbers, summing to 1 // STEP 3 — blend c = Σᵢ α[i] · H[i] // one 512-vector // STEP 4 — decode and advance s = RNN(s, embed(prev_word), c) word = softmax(W_o · s + b_o) emit(word) // Note: H[i] is read but never written. s is overwritten every pass.
Section 07

Where H Comes From — The BiRNN Encoder

Now that you know what H is for, here's how it's built. Bahdanau uses a bidirectional RNN so that each h_i sees the whole sentence, not just the words before it.

FIG 8 — Building H. Two RNN passes in opposite directions, concatenated per position. The bottom row is H.
// Forward pass — sees x₁ … xᵢ →hᵢ = RNN_fwd(xᵢ, →hᵢ₋₁) // Backward pass — sees x_Tx … xᵢ ←hᵢ = RNN_bwd(xᵢ, ←hᵢ₊₁) // Join them — this row goes into H hᵢ = [ →hᵢ ; ←hᵢ ] // 256 + 256 = 512 numbers
Why bidirectional matters for attention: in a one-directional RNN, h₁ only knows about "I" — it has no idea the sentence is about India. That makes it a poor thing to score against. Bidirectionality means every row of H is a genuinely complete description of its word in context, which is what makes the scoring meaningful.
Section 08

What the Decoder Does With c_t

The context vector isn't the final answer — it's an ingredient. The decoder combines it with its own state and the previous word to update itself and produce output.

// Update the decoder state using three inputs s_t = RNN( s_{t−1}, [ E(y_{t−1}) ; c_t ] ) ↑ my state ↑ last word ↑ what I just looked at // Produce the word distribution over the vocabulary P(y_t | y_<t, X) = softmax( W_o · tanh(W_c·[s_t ; c_t]) + b_o ) // Training loss — plain cross-entropy over the target sequence L = − Σ_t log P(y_t* | y*_<t, X)
How does attention learn without alignment labels? Nobody tells the model that "India" should align with "l'Inde". The gradient does it. If putting weight on h₃ produces a better prediction, the loss goes down, and gradient descent nudges W_a/U_a/v_a to score h₃ higher next time in that situation. Alignment is a by-product of minimizing translation error.
// The gradient path — how the alignment network gets trained Loss → output softmax → s_t and c_t → α_{t,i} → e_{t,i} → W_a, U_a, v_a, b_a ↑ the α values are differentiable because softmax and weighted-sum are both smooth
Why this only works with soft attention: if attention picked exactly one source word (hard attention), the selection would be a discrete choice — not differentiable, so no gradient could flow back to the alignment network. The soft weighted average is what makes end-to-end training possible.

Section 09

Attention Variants

Every variant keeps the same three-part skeleton — score, normalize, blend. They differ only in the scoring function and in which positions are allowed to be scored.

Variant Score formula What changed Use when
Bahdanau (additive) v_aᵀ tanh(W_a s_{t−1} + U_a h_i + b_a) The baseline; uses previous state s_{t−1} Encoder and decoder sizes differ
Luong dot s_tᵀ h_i No learned parameters at all — just a dot product Fast; dimensions must match
Luong general s_tᵀ W_a h_i One matrix instead of three Flexible, cheaper than additive
Luong concat v_aᵀ tanh(W_a[s_t ; h_i]) Concatenates instead of adding Similar power to additive
Scaled dot-product qᵀk / √d_k Adds the √d_k division Foundation of the Transformer
Bahdanau vs Luong — the timing difference students miss: Bahdanau computes attention using s_{t−1}, the state before the RNN update, then feeds c_t into the update. Luong updates the RNN first to get s_t, then computes attention and combines afterwards. Same components, different order in the loop.
Global attention
  • Scores every source position
  • Any word can be reached
  • Cost O(T_x · T_y)
Local attention
  • Scores only a window around a predicted position
  • Cheaper and more focused
  • May miss distant dependencies
Soft attention
  • Weighted average over all positions
  • Differentiable → trains with plain backprop
  • Never fully ignores anything
Hard attention
  • Picks exactly one position
  • Sparse and interpretable
  • Not differentiable — needs REINFORCE

Checklist — can you answer these?

Question Answer
What is H? The encoder's output — one context-aware vector per source word, stacked into a matrix. Computed once, then frozen.
What is c_t? A weighted average of the rows of H, using the α values as proportions. Same size as one h_i.
What is α? The attention weights — computed fresh each decoder step, all in [0,1], summing to 1.
Which "weights" are learned? W_a, U_a, v_a, b_a only. α is computed, never stored or learned.
Why softmax and not simple division? Raw scores can be negative; exponentiating forces positivity, and dividing by the sum makes them proportions.
Why does α change each step? Because s_{t−1} changes each step. H is constant, so the decoder state is the only thing driving the difference.
Why "additive"? The projected query and key are added before tanh. Luong multiplies instead.
Who labels the alignments? Nobody. They emerge from minimizing translation loss via backprop.
Why must attention be soft? Hard selection isn't differentiable, so no gradient could reach the alignment network.
How does this become a Transformer? Rename s_{t−1} → Q and H → K, V; swap the additive score for a scaled dot product; drop recurrence.
