Section 01

Why Multimodal AI?

Most of the information humans reason about isn't text. A product review references a photo; a medical record includes an X-ray; a legal document is a scanned PDF with tables and signatures, not clean plaintext. Multimodal AI builds models that perceive and reason across more than one modality — typically vision and language — instead of assuming everything can be reduced to text first.

ModalityExample dataWhy text alone loses information
VisionPhotos, charts, diagrams, scanned documentsLayout, spatial relationships, and visual detail have no faithful text encoding
AudioSpeech, tone, musicProsody, emphasis, and non-verbal cues vanish in a transcript
Structured/tabularSpreadsheets, database recordsRow/column relationships are lost when flattened to a text string
The practical driver, not just the academic one: a huge fraction of real enterprise data — invoices, contracts, product catalogs, ID documents — exists natively as images or scanned PDFs, not clean text. Module 5 Part 4's applications (OCR pipelines, document intelligence, multimodal RAG) exist because that's where multimodal AI's economic value concentrates, not primarily because vision benchmarks needed improving.
Section 02

Limitations of Text-Only Models

Every LLM covered in Module 1 is fundamentally a text-token predictor. That has real, structural consequences once the task involves anything visual.

✗

No access to layout

A table's column alignment, a form's field positions — invisible to a model that only sees a token stream.

✗

Lossy OCR-first pipelines

Running OCR then feeding text to an LLM discards everything OCR itself can't capture (charts, photos, handwriting).

✗

Can't ground claims in an image

"Does this X-ray show a fracture?" has no meaningful text-only answer — there's no text to retrieve it from.

✗

Blind to visual context

A screenshot bug report, a whiteboard photo, a hand-drawn diagram — all illegible to a text-only model.

Exam favourite: "Why is OCR-then-LLM not the same as a true multimodal model?" — OCR is a lossy, one-way conversion: it discards layout, visual emphasis, non-text visual content (photos, charts, diagrams), and any information encoded spatially rather than textually. A true vision-language model (Part 2a) reasons over the raw visual signal directly, without that irreversible information loss.
Section 03

Representation Learning Across Modalities

The foundational question multimodal AI has to answer: how do you represent an image and a sentence in a form a single model can reason over together? The answer, in every modern system, is the same idea Module 3 §01 introduced for text — embed everything into a shared vector space — extended across modalities.

FIG 1 — Two separate encoders (one per modality), trained so that matching image-text pairs land close together in a single shared vector space — the same cosine-similarity geometry as Module 3's text embeddings, now spanning modalities instead of just spanning documents.
This is the single idea the rest of Module 5 elaborates on. Part 2a's contrastive learning is how that shared space gets trained. Part 4's multimodal retrieval and multimodal RAG are applications of exactly this shared space, extending Module 3's text-only retrieval to also retrieve images by meaning.
Section 04

How Multimodal AI Evolved: Models, Architectures and Training Techniques

Multimodal models did not appear in one step. Each generation changed one of three things: how each modality is encoded (hand-crafted features → CNNs → Transformers), how the modalities are fused (concatenation → cross-attention → shared embedding space → tokens inside an LLM), and where the supervision comes from (small human-labelled datasets → web-scale image–text pairs → instructions written by LLMs → human preferences). 1

Supervised captioning / VQA — copy what a human wrote

In everyday terms: A student with an answer key: for every photo, a person wrote the correct caption or answer, and the model is marked word by word.

  1. A photo goes into an image encoder (a CNN in 2015), which turns it into a vector.
  2. A text decoder (an LSTM) writes a caption one word at a time from that vector.
  3. Each word is compared with the human-written caption. A wrong word (“cat” instead of “dog”) gives a high loss, and training adjusts the weights so “dog” becomes more likely next time. VQA works the same way, but picks one answer from a fixed list.

FIG 2 · Real use: MS-COCO (~120K photos × 5 captions), VQAv2 (~1.1M questions). Strong on that one task, but every label costs human time, so data stays small.

Why it appeared

Before 2014, captioning systems detected objects and filled a template (“There is a dog on the beach”). Deep learning made it possible to train one network end to end, from pixels to words, if enough human-written examples existed.

Input → output

Captioning: a 224×224×3 photo → CNN → one feature vector (for example 2,048 numbers) → LSTM → a sentence, one word at a time from a vocabulary of about 10K words.

VQA: photo + question → one answer chosen from a fixed list (the 1,000 most frequent answers in the training set).

What is trained · what is frozen

Everything is trained on the task: the LSTM (or answer classifier) from scratch, and the CNN usually starts from ImageNet weights and is fine-tuned or kept fixed.

Training objective, in maths and in words
// captioning: maximise the probability of the human caption, word by word L = − Σ_t log p( w_t | image, w_1 … w_(t−1) ) // VQA: ordinary classification over the answer list L = − log p( correct answer | image, question )

During training the model is always fed the true previous words (“teacher forcing”), so each word is a separate small classification problem: “given the photo and the words so far, which word comes next?”

Worked example: the terrier photo

Human caption: “a dog runs out of the sea with a ball”. At step 2 an untrained model gives p(“dog”) = 0.2, so the loss for that word is −ln 0.2 = 1.61. After training, p(“dog”) = 0.9 and the loss is −ln 0.9 = 0.11.

VQA: “What is in the dog's mouth?” → the model must pick “ball” out of its 1,000-answer list.

Strengths
  • Simple and direct: the output is exactly what is scored.
  • Clear metrics (BLEU, CIDEr for captions; accuracy for VQA).
  • Works with modest data for one well-defined task.
Limitations
  • Every label costs human time, so datasets stay small (MS-COCO: ~120K images).
  • One model per task; a captioner cannot answer questions.
  • A fixed answer list cannot express new answers.
  • Models learn shortcuts from the language alone: “What colour is the banana?” → “yellow” without looking. VQAv2 (2017) added balanced image pairs with different answers to counter this.
Check yourself: Why can a 2016 VQA model never answer “a tennis ball and a stick”?

Because VQA was trained as classification over a fixed list of frequent answers. An answer that is not in the list has no output unit, so the model cannot produce it however well it sees the image.

2

Masked modelling + image–text matching — hide parts, guess them back

In everyday terms: A fill-in-the-blanks worksheet: the photo and caption are given with pieces hidden, and the model must fill them in.

  1. Hide a patch of the photo (here, the ball).
  2. Hide a word of the caption (here, “dog”).
  3. A Transformer reads the photo pieces and the words together. To recover “dog” it must look at the photo; to recover the ball patch it can use the word “ball”, so it learns how the two modalities relate.
  4. Image–text matching: swap captions between photos in the batch and train a yes/no classifier: does this caption belong to this photo?

FIG 3 · Real use: ViLBERT, LXMERT, UNITER (2019–20), trained on ~3–9M image–caption pairs. No human labelling beyond the captions.

Why it appeared

BERT (2018) showed that pretraining on unlabelled text and then fine-tuning beats training each task from scratch. Researchers applied the same recipe to image–caption pairs, which are far cheaper to collect than task labels.

Input → output

The photo goes through an object detector (Faster R-CNN), which returns about 36 region features (2,048 numbers each, plus the box position). The caption becomes word tokens.

One sequence, [CLS] words [SEP] regions, enters a Transformer. Out comes one contextual vector per word and per region. Single-stream models (VisualBERT, UNITER) mix everything in one Transformer; two-stream models (ViLBERT, LXMERT) keep one per modality and connect them with co-attention.

What is trained · what is frozen

The Transformer is pretrained with these losses; the object detector is usually kept fixed. For each downstream task (VQA, retrieval, grounding), a small head is added and the whole model is fine-tuned again.

Training objective, in maths and in words
// three losses, added together L_MLM = − log p( masked word | other words, all regions ) // ~15% of words hidden L_MRM = − log p( object class of masked region | everything else ) // or regress its features L_ITM = − [ y log s + (1 − y) log(1 − s) ] // s = P(match) from [CLS] L = L_MLM + L_MRM + L_ITM

For ITM, half of the pairs keep their true caption (y = 1) and half get a random caption from another image (y = 0). The [CLS] vector must decide which.

Worked example: the terrier photo

Caption “a [MASK] runs out of the sea with a ball”. From text alone, “dog”, “man” or “horse” all fit. The region showing the terrier makes “dog” the clear winner, so the model learns to link that region to the word.

ITM negative: the photo paired with “a red car parked on a street” → target y = 0.

Strengths
  • One pretrained model transfers to many tasks.
  • Learns explicit word–region links (“ball” ↔ the ball's box).
  • No task labels needed for pretraining, only captions.
Limitations
  • Depends on a slow object detector, and cannot see what the detector misses.
  • Still needs fine-tuning for every task.
  • Every image–text pair needs a full joint forward pass (a cross-encoder). Searching 1M images for one query means 1M Transformer runs.
  • Data stayed at 3–10M pairs, tiny next to what came later.
Check yourself: Why is image search with UNITER slow, while CLIP search is fast?

UNITER reads the image and the text together, so the score for every pair needs its own forward pass. CLIP encodes images and texts separately (a dual encoder): you embed 1M images once, store the vectors, and each query is one text encoding plus fast dot products.

3

Contrastive learning — pull matching pairs together, push the rest apart

In everyday terms: A matching game: shuffle a pile of photos and captions, and score the model on pairing each photo with its own caption.

  1. Encode every photo and every caption in the batch into vectors.
  2. Compare every photo with every caption (the grid). The true pairs are on the diagonal, and the label is free: the caption each photo was published with.
  3. The loss raises the diagonal scores and lowers the rest. After millions of batches, each photo sits right next to its caption in one shared space, and unrelated items are far apart.

FIG 4 · Real use: CLIP (400M pairs) and ALIGN (1.8B pairs), 2021. The maths, with these same numbers, is in Part 2a §03.

Why it appeared

Predicting the exact caption of a noisy web image is very hard and wasteful. OpenAI found it far easier to ask only “which caption belongs to this image?” With that simpler task, hundreds of millions of free web pairs became usable, and the model could recognise categories it was never given labels for (zero-shot).

Input → output

Image → image encoder (ViT or ResNet) → one vector. Text → text Transformer → one vector. Both are projected to the same size (for example 512) and L2-normalised, so their dot product is the cosine similarity.

The two towers never see each other's input: this is a dual encoder, and vectors can be precomputed and cached.

What is trained · what is frozen

Both encoders, both projection layers and the temperature τ are trained together, from scratch. Nothing is frozen.

Training objective, in maths and in words
// N pairs per batch, S_ij = cosine(image_i, text_j), τ = temperature L_img = − (1/N) Σ_i log [ exp(S_ii/τ) / Σ_j exp(S_ij/τ) ] // each image picks its caption L_txt = − (1/N) Σ_i log [ exp(S_ii/τ) / Σ_j exp(S_ji/τ) ] // each caption picks its image L = (L_img + L_txt) / 2

Each row of the N × N grid is an N-way multiple-choice question whose right answer is the diagonal. The softmax turns similarities into probabilities, and the loss rewards a high probability on the true pair.

Worked example: the terrier photo

Batch of three: the terrier photo, a car photo and a cat photo, with “a dog”, “a car” and “a cat”. Row 1 similarities = [0.9, 0.1, 0.2]. With τ = 0.1 the logits become [9, 1, 2], softmax gives P(“a dog”) = 0.9988 and the loss is 0.0012. The full derivation is in Part 2a §03.

Strengths
  • Free supervision from the web, so it scales to 400M–5B pairs.
  • Zero-shot classification: write labels as sentences and pick the closest.
  • Very fast retrieval, because embeddings are precomputed.
  • Its image encoder became the “eyes” of most later VLMs.
Limitations
  • Can score a pair, but cannot write any text.
  • Behaves like a bag of words: “a mug in the grass” ≈ “grass in a mug”.
  • Weak at counting, spatial relations and specialised domains.
  • Needs very large batches and compute; inherits web biases.
Check yourself: How does CLIP classify a photo into classes it was never trained on?

Write each class as a sentence (“a photo of a terrier”, “a photo of a poodle” …), embed the sentences with the text encoder, embed the photo with the image encoder, and pick the sentence with the highest cosine similarity. No training on those classes is needed.

4

Frozen-model bridging — train only a small connector

In everyday terms: Two experts who speak different languages, a vision expert and a language expert, plus a small interpreter between them. Only the interpreter is trained.

  1. The photo goes through a pretrained, frozen vision encoder: its weights never change.
  2. A small bridge (a Q-Former or Perceiver Resampler) turns the vision features into a few vectors the language model can read. It is the only part that learns.
  3. The frozen language model answers. Its error is sent back through it to the bridge, so the bridge learns to “translate” better, while the two big models stay exactly as they were.

FIG 5 · Real use: Flamingo (2022), BLIP-2 (2023), Llama 3.2 Vision adapters. Cheap to train, and the language model keeps all its text skills.

Why it appeared

By 2022 there were excellent pretrained vision encoders and large language models. Training both again is very expensive, and fine-tuning a large LLM on image data risks damaging its language skills (catastrophic forgetting). The cheaper idea: keep both frozen and train only a small connector between them.

Input → output

BLIP-2: photo → frozen ViT-g → 257 × 1,408 features → Q-Former: 32 learned query vectors read those features through cross-attention → 32 × 768 → linear layer → 32 vectors of the LLM's width (2,560 for OPT-2.7B) → placed in front of the text prompt.

Flamingo: a Perceiver Resampler outputs 64 visual tokens, read by new gated cross-attention layers inserted into the frozen LLM.

What is trained · what is frozen

Trained: the bridge only (BLIP-2: about 188M parameters out of roughly 3.9B in total, under 5%). Frozen: the vision encoder and the LLM, whose weights never change.

Training objective, in maths and in words
// the usual next-word loss, but only the bridge's weights φ are updated L(φ) = − Σ_t log p_LLM( w_t | bridge_φ(image), w_1 … w_(t−1) ) // θ_ViT, θ_LLM fixed // Flamingo's gated layer: output added to the frozen layer, scaled by tanh(α) h ← h + tanh(α) · CrossAttn(h, visual tokens) // α = 0 at the start → tanh(0) = 0

The gradient flows backwards through the frozen LLM into the bridge. The LLM is used as a fixed judge: the bridge learns to produce whatever vectors make the LLM write the right words.

Worked example: the terrier photo

Prompt: [32 visual vectors] + “Question: what is the dog carrying? Answer:”. The frozen OPT continues with “a tennis ball”. If it had said “a stick”, the loss on “tennis ball” would flow back and adjust only the Q-Former.

Strengths
  • Cheap: a small fraction of the parameters is trained.
  • The LLM keeps all its text abilities.
  • Modular: swap in a better LLM or vision encoder and retrain only the bridge.
  • Flamingo gains few-shot learning from interleaved web pages.
Limitations
  • 32–64 visual tokens compress the image hard: small text and small objects get lost.
  • Cannot exceed what the frozen parts already know.
  • Flamingo's approach changes the LLM's architecture (new layers inside it).
Check yourself: Why is Flamingo's gate α initialised to 0?

Because tanh(0) = 0, so at the start the new cross-attention layers add nothing and the model is exactly the original language model. Vision is blended in gradually as α grows, which protects the LLM's language ability early in training.

5

Visual instruction tuning — teach the model to follow requests about images

In everyday terms: Practice exams: a strong tutor writes question-and-answer sheets about pictures, and the student practises until it answers what is asked.

  1. Describe a photo as text only: its human caption and the coordinates of the objects in it (the coloured boxes).
  2. A text-only GPT-4 reads that description and writes questions and answers as if it could see the picture.
  3. Train the VLM on (image + question → answer). Only the answer words count toward the loss; the image and question are just context.
  4. Result: before, the model just describes the scene; after, it actually answers the question asked.

FIG 6 · Real use: LLaVA (2023): 158K GPT-4-written examples, about one day of training on 8 GPUs. Now the standard second stage of open VLMs.

Why it appeared

Earlier models could caption or answer short VQA questions but did not follow open requests such as “explain why this is funny” or “write a short story about this photo”. Text LLMs had learned this through instruction tuning, but in 2023 no multimodal instruction data existed.

Input → output

Photo → CLIP ViT-L/14 → 576 patch vectors (336px input, 1,024 numbers each) → MLP projector → 576 vectors of the LLM's width (4,096 for a 7B LLM) → inserted where <image> appears in the chat prompt → the LLM writes the answer.

What is trained · what is frozen

Trained: the projector (stage 1), then projector + LLM (stage 2). Frozen: the CLIP vision encoder.

Training objective, in maths and in words
// next-token loss, counted ONLY on the answer tokens L = − Σ_(t ∈ answer) log p( a_t | image, instruction, a_1 … a_(t−1) ) // in code: question and image positions get label −100 (PyTorch's ignore_index)

Two stages. Stage 1 (alignment): only the projector is trained, on 558K image–caption pairs, so CLIP features land where the LLM expects word vectors. Stage 2 (instruction tuning): projector + LLM are trained on 158K–665K instruction examples. The vision encoder stays frozen throughout.

Worked example: the terrier photo

GPT-4 never sees the photo. It receives text: “Caption: a dog runs out of the sea with a ball. Boxes: dog [0.21, 0.30, 0.62, 0.88], ball [0.40, 0.33, 0.47, 0.41]”. It writes: Q “What might the dog do next?” A “It will probably bring the ball back to its owner so it can be thrown again.” The VLM then learns (photo + Q → A).

Strengths
  • Turns a VLM into a general assistant that follows requests.
  • Cheap and open: LLaVA-1.5 trains in about a day on 8 GPUs.
  • The two-stage recipe is now standard for open VLMs.
Limitations
  • GPT-4 wrote answers from captions, so some data mentions details not visible in the photo, which encourages hallucination.
  • Inherits the LLM's own hallucination and biases.
  • 576+ image tokens per photo make sequences long and inference costly.
Check yourself: Why is the loss not computed on the question tokens?

The question is given by the user at inference time; the model never needs to generate it. Training on it would waste capacity on predicting user text and could teach the model to ask questions instead of answering them. Only the answer is what we want the model to produce.

6

Preference tuning (RLHF / DPO) — learn which answer is better

In everyday terms: A judge at a debate: instead of writing the perfect answer, a person simply says which of two answers is better.

  1. Give the model a photo and an instruction.
  2. Let it write two different answers. Here, answer B invents a brown dog, a red frisbee and a park, none of which are in the photo.
  3. A person (or an AI judge) picks the better answer: A.
  4. Update the model so answers like A become more likely and answers like B less likely, either through a reward model and reinforcement learning (RLHF) or directly (DPO).

FIG 7 · Real use: LLaVA-RLHF and RLHF-V (2023). The main training-time tool against hallucination (Part 3 §03).

Why it appeared

Instruction-tuned VLMs often hallucinate: they describe objects that are not in the image because the language model's habits (a beach often has a frisbee, an umbrella …) override what is seen. Copying good answers does not teach the model what not to say; comparing a good and a bad answer does.

Input → output

Training data: (image, instruction, answer A, answer B, which is better). Output: the same VLM, now more likely to produce answers like the preferred one.

What is trained · what is frozen

Trained: the VLM (the “policy”, usually LLM + projector). Frozen: a copy of the starting model, used as the reference π_ref. RLHF also trains a separate reward model.

Training objective, in maths and in words
// RLHF step 1: reward model r from comparisons (Bradley–Terry) P(A better than B) = σ( r(A) − r(B) ) // σ = sigmoid // RLHF step 2: maximise reward, but stay close to the original model π_ref maximise E[ r(x, y) ] − β · KL( π ‖ π_ref ) // DPO: skip the reward model, train directly on the pair (w = preferred, l = rejected) L_DPO = − log σ( β · [ log π(y_w|x)/π_ref(y_w|x) − log π(y_l|x)/π_ref(y_l|x) ] )

The KL term (or the π_ref ratio in DPO) stops the model from drifting far from its starting behaviour just to please the judge.

Worked example: the terrier photo

Answer A: “A small terrier runs out of the sea carrying a tennis ball.” Answer B invents a brown dog, a red frisbee and a park. The reward model scores r(A) = 2.0, r(B) = −1.0, so P(A better) = σ(3) = 0.95.

DPO with β = 0.1: if the log-ratio gap is 5, the loss is −log σ(0.5) = −log 0.62 = 0.47. Training widens the gap and the loss falls.

Strengths
  • Judging which answer is better is easier and cheaper than writing a perfect one.
  • Directly targets hallucination, helpfulness and safety.
  • DPO is simple: no reward model and no reinforcement-learning loop.
Limitations
  • Reward hacking: the model learns what the judge likes (for example longer answers) rather than what is true.
  • Human comparisons are costly; AI judges carry their own biases.
  • Too strong a push can make the model evasive or overly cautious.
Check yourself: What would go wrong without the KL penalty (or reference model)?

The model could drift to strange outputs that happen to score high with the reward model (reward hacking) and lose fluency or knowledge it had. The KL term keeps it close to the original model, so it only changes where the preference data tells it to.

7

Native multimodal pretraining — one model, one sequence, every modality

In everyday terms: A child who grows up seeing, hearing and reading at the same time, rather than an adult who learns to read first and is shown pictures later.

  1. Each input is turned into tokens: words for text; for images, every patch becomes a code from a learned codebook; audio clips become audio codes.
  2. All the tokens are mixed into one sequence, in the order they appear.
  3. One Transformer is trained from scratch to predict the next token, whatever its type. Because outputs are tokens too, the same model can reply in text, generate images or speak.

FIG 8 · Real use: Gemini (2023), Chameleon and GPT-4o (2024). The most capable approach, and by far the most expensive to train.

Why it appeared

“Bolt-on” models (cards 4–5) learn language first and are shown images later, so cross-modal reasoning is limited and they can only read images, not produce them. Training one model on all modalities from the start lets the connections form during pretraining and lets the model output any modality.

Input → output

Text → word tokens. Image → a learned image tokenizer (VQ): Chameleon turns a 512×512 image into 1,024 discrete codes from a codebook of 8,192. Audio → codec tokens. Everything goes into one sequence with markers such as <image_start> … <image_end>. Output: the next token, of any type.

What is trained · what is frozen

Everything is trained from scratch, together, on trillions of mixed tokens. Nothing is frozen.

Training objective, in maths and in words
// one loss for everything: predict the next token, whatever its modality L = − Σ_t log p( token_t | token_1 … token_(t−1) ) // text, image and audio tokens alike

Because an image is just a run of tokens from the shared vocabulary, “generate an image” is the same operation as “generate a sentence”: keep predicting the next token, then decode the image codes back into pixels.

Worked example: the terrier photo

Sequence: “Here is my dog:” <image_start> [1,024 image codes of the terrier] <image_end> “He loves running on the” → the model predicts “beach”. Asked “draw him with a red ball”, it predicts image codes instead of words.

Strengths
  • The strongest cross-modal reasoning.
  • Any input to any output: text, images, speech, interleaved documents.
  • One model instead of a pipeline of parts.
Limitations
  • Enormous cost: only frontier labs can train it.
  • Training is less stable (Chameleon needed extra normalisation tricks).
  • Many image tokens make sequences long; VQ codes lose fine detail such as small text.
  • Gemini's and GPT-4o's exact designs are undisclosed.
Check yourself: Why does turning images into discrete tokens let one model both read and draw images?

Once images are tokens in the same vocabulary as words, reading an image and writing one are both next-token prediction. The model can take image tokens as input and emit image tokens as output, and a decoder turns the emitted codes back into pixels.

Key Takeaways & Exam Prep

✓

Most real-world data isn't text

Multimodal AI's value concentrates where enterprise data actually lives: scanned documents, photos, forms.

✓

Text-only models are structurally blind to layout

No amount of prompting recovers information a token stream never captured.

✓

OCR-then-LLM is lossy, not equivalent

A genuine vision-language model reasons over raw visual signal directly.

✓

Shared embedding space is the core mechanism

Separate encoders per modality, trained so matching content lands close together.
