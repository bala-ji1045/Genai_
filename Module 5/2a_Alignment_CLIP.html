Section 01

What “Alignment” Means, and What This Part Covers

Part 1 (§03) ended with one idea: put images and text into a shared vector space. This Part explains, in full, how that space is built. The model that made it work at scale is CLIP (OpenAI, 2021), so CLIP is the backbone of this Part.

The problem in plain words

An image encoder turns a photo into a list of numbers, say 512 of them. A text encoder turns a sentence into another list of 512 numbers. If the two encoders are trained separately, those numbers mean completely different things: it is like two maps of the same city drawn with different coordinate systems. Position 17 in the image vector has no relation to position 17 in the text vector, so comparing the two vectors is meaningless.

Alignment means training both encoders together so they share one coordinate system: a photo of a dog and the sentence “a photo of a dog” end up at nearly the same point, and a photo of a car ends up far from both. Once that is true, “does this image match this text?” becomes a simple calculation: the cosine similarity of two vectors.

// what alignment changes (illustrative cosine similarities for one dog photo) "a photo of a dog" "a photo of a car" "a photo of a cat" before training 0.02 −0.01 0.03 // random: no meaning after training 0.31 0.12 0.21 // the right caption wins

Section 02

How a Vision Transformer (ViT) Turns an Image into Tokens

Text models read tokens. The Vision Transformer (Dosovitskiy et al., 2020) made images look like tokens too, which is why the same Transformer machinery from Module 1 now works on pictures. Almost every vision encoder in this guide (CLIP's ViT-L/14, EVA-CLIP, SigLIP, Qwen2-VL's encoder) is a ViT.

FIG 1 — A ViT treats an image as a sentence of patches. CLIP uses the CLS output as “the image”; LLaVA-style VLMs use the per-patch outputs (“grid features”) as a sequence of visual tokens.

The arithmetic you should be able to do

// number of visual tokens = (image side / patch side)² ViT-B/16 at 224px: (224/16)² = 14² = 196 patch tokens (+1 CLS) ViT-L/14 at 224px: (224/14)² = 16² = 256 patch tokens (+1 CLS) // LLaVA v1 ViT-L/14 at 336px: (336/14)² = 24² = 576 patch tokens (+1 CLS) // LLaVA-1.5 // each patch, flattened: patch_h × patch_w × 3 channels 16 × 16 × 3 = 768 raw numbers → linear projection to model width D // self-attention cost grows with the SQUARE of the token count 576 tokens vs 196 tokens → (576/196)² ≈ 8.6× more attention compute

Inside a ViT, step by step with shapes (CLIP ViT-B/32)

One attention head, the operation inside step ⑤, is the same as in Module 1's text Transformer:

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) V // d_k = 64 per head // Q, K, V are the 50 token vectors times three learned matrices. // Row i of softmax(Q Kᵀ/√d_k) says how much patch i looks at every other patch.

Why ViT and not a CNN? CNNs (ResNets) bake in locality: each layer only looks at a neighbourhood. A ViT's self-attention lets any patch attend to any other from layer 1, and it scales smoothly with data and compute. With little data, CNNs win (their built-in assumptions help); with hundreds of millions of image–text pairs, ViTs win. CLIP trained both kinds and its best model was a ViT (ViT-L/14).
Section 03

The Contrastive Loss, Its Gradient, and Why Temperature and Batch Size Matter

Goal: train an image encoder f and a text encoder g so that a photo and its caption land close together, and unrelated pairs land far apart — using only (image, caption) pairs scraped from the web, with no class labels at all.

Step 1 — Embed and normalise

For a batch of N pairs, compute image embeddings x_i = f(image_i) and text embeddings y_i = g(text_i), project both to the same dimension d (512 for CLIP ViT-B, 768 for ViT-L/14), and L2-normalise them so that a dot product is the cosine similarity.

Step 2 — Build the N × N similarity matrix

S_ij = x_i · y_j. The diagonal holds the true pairs; every off-diagonal cell is a mismatched pair. With N = 32,768 (CLIP's batch), that is about a billion comparisons per step — and every one is free supervision.

Step 3 — Turn each row into a classification problem

// InfoNCE (image → text direction): "which of the N texts belongs to image i?" L_img = −(1/N) Σ_i log [ exp(S_ii / τ) / Σ_j exp(S_ij / τ) ] // the same thing column-wise (text → image): "which of the N images belongs to text i?" L_txt = −(1/N) Σ_i log [ exp(S_ii / τ) / Σ_j exp(S_ji / τ) ] // CLIP's final loss is the symmetric average L = (L_img + L_txt) / 2 // τ = temperature (CLIP learns log(1/τ); initialised at τ = 0.07, logit scale capped at 100) // This is exactly softmax cross-entropy with "label = the diagonal index".

Worked example: 3 pairs, and why temperature matters

Suppose a batch of three pairs — (dog photo, “a dog”), (car photo, “a car”), (cat photo, “a cat”) — gives this cosine-similarity matrix:

“a dog”“a car”“a cat”
dog photo0.90.10.2
car photo0.20.80.3
cat photo0.10.30.7
// Row 1 (dog photo), temperature τ = 1 → logits are the raw similarities exp(0.9) = 2.4596 exp(0.1) = 1.1052 exp(0.2) = 1.2214 sum = 4.7862 P(correct) = 2.4596 / 4.7862 = 0.514 loss = −ln(0.514) = 0.666 // Same row, τ = 0.1 → logits are similarities × 10 = [9, 1, 2] exp(9) = 8103.08 exp(1) = 2.72 exp(2) = 7.39 sum = 8113.19 P(correct) = 8103.08 / 8113.19 = 0.9988 loss = −ln(0.9988) = 0.0012 // Whole batch (symmetric loss): τ = 1 → 0.744 τ = 0.1 → 0.011

What this shows. The embeddings are identical in both cases; only τ changed. A small τ turns modest similarity gaps (0.9 vs 0.2) into near-certain predictions, so the gradient focuses on the pairs that are still confused (the hard negatives). Too small and training becomes unstable; that is why CLIP learns τ and caps the logit scale at 100.

The gradient: what one training step actually does

Write the logits of row i as z_ij = S_ij / τ and the softmax probabilities as p_ij. The derivative of a softmax cross-entropy has a famously simple form:

// derivative of the row loss L_i with respect to each logit ∂L_i / ∂z_ij = p_ij − 1[j = i] // prediction − target (target = 1 on the diagonal) // pushed back to the image embedding x_i (before the normalisation step) ∂L_i / ∂x_i = (1/τ) · ( Σ_j p_ij · y_j − y_i ) // "where the model currently points" minus "where the true caption is"

Gradient descent moves x_i in the opposite direction: towards its own caption y_i and away from a probability-weighted average of the other captions. Captions the model currently confuses with the right one have high p_ij, so they get pushed away hardest. Hard-negative mining happens automatically, without any extra code.

// Row 1 of the worked example (dog photo), τ = 1: p = [0.514, 0.231, 0.255] gradient on logits = [0.514 − 1, 0.231, 0.255] = [−0.486, +0.231, +0.255] // → raise S(dog, "a dog"); lower S(dog, "a cat") a little MORE than S(dog, "a car"), // because "a cat" (0.2) was the more confusable caption than "a car" (0.1) // Same row, τ = 0.1: p = [0.9988, 0.0003, 0.0009] gradient w.r.t. S = (p − target) / τ = [−0.0125, +0.0034, +0.0091] // → the pair is nearly solved, so the step is small; "a cat" still gets 2.7× the push of "a car"

  • τ very large: every probability tends to 1/N and the loss to log N, whatever the embeddings are. Nothing can be learned.
  • τ very small: the softmax becomes a hard maximum, so only the single hardest negative matters. Gradients become spiky and training unstable.
  • CLIP's choice: learn t = log(1/τ) as a parameter, starting at log(1/0.07) ≈ 2.66 (scale 14.3), and clip the scale at 100. Learning the log keeps τ positive and makes updates smooth.

Why bigger batches help: the information view

InfoNCE was introduced with a guarantee (van den Oord et al., 2018): it gives a lower bound on the mutual information between the two views.

I( image ; text ) ≥ log N − L_InfoNCE // N = 3 → the bound can never exceed log 3 = 1.10 nats // N = 32,768 → the bound can reach up to log 32,768 = 10.40 nats // Sanity check for your own training: at initialisation all similarities are about equal, // so every p_ij ≈ 1/N and the loss starts at about ln N (≈ 10.4 for CLIP's batch).

In plain words: with a small batch, picking the right caption out of a few is easy, so the model only needs coarse features. With 32,768 candidates there are many near-misses, and only fine-grained features can tell them apart. Batch size is the size of the multiple-choice question.

Why no labels are needed: the “label” for image i is simply “the caption it was published with”. This is the same trick as LLM pretraining (the label for token t is the next token in the text that already exists), applied to pairs. The internet supplies the supervision for free.
Why batch size is the negative budget: each image is contrasted against N − 1 negatives. At N = 32 the negatives are mostly easy (“a dog” vs “a spreadsheet”); at N = 32,768 there are many near-misses (“a husky” vs “a malamute”), which forces fine-grained features. This is also why CLIP training is memory-hungry: the N × N matrix must be gathered across all GPUs.

FIG 2 — CLIP is a dual encoder. Because images and texts are encoded separately, embeddings can be precomputed and cached: that is what makes CLIP fast for retrieval and zero-shot classification.

Before CLIP: why this was a leap

Learning visual concepts from captions was not new. In 2017, Visual N-Grams (Li et al.) tried zero-shot ImageNet classification from web text and reached 11.5% top-1. CLIP reached 76.2% with the same idea at a much larger scale and with a contrastive objective. The design table below explains which choices closed that gap.

End to end: one example through both towers (ViT-B/32 CLIP)

// TEXT TOWER "a photo of a dog" → byte-pair tokens: [SOS] a photo of a dog [EOS] // vocabulary 49,152; padded to 77 positions → token embedding (49,152 × 512) + position embedding (77 × 512) → 77 × 512 → 12 Transformer layers, width 512, 8 heads, causal mask → 77 × 512 → take the vector at the [EOS] position, LayerNorm → 512 → projection W_t (512 × 512), L2-normalise → text embedding (512) // IMAGE TOWER (§02) 224 × 224 × 3 → 49 patches + [CLS] → 12 ViT blocks → [CLS] → W_i (768 × 512) → image embedding (512) // THE BATCH I_e : 32,768 × 512 T_e : 32,768 × 512 logits = exp(t) · I_e · T_eᵀ → 32,768 × 32,768 // ≈ 1.07 billion scores

The training step, exactly as in the paper

# Numpy-style pseudocode from the CLIP paper (Figure 3) I_f = image_encoder(I) # [n, d_i] e.g. ViT CLS outputs T_f = text_encoder(T) # [n, d_t] activations at the [EOS] token I_e = l2_normalize(I_f @ W_i, axis=1) # [n, d_e] joint embedding T_e = l2_normalize(T_f @ W_t, axis=1) # [n, d_e] logits = (I_e @ T_e.T) * exp(t) # [n, n] t = learned log temperature labels = arange(n) # the diagonal loss = (cross_entropy(logits, labels, axis=0) + cross_entropy(logits, labels, axis=1)) / 2

Training at scale: the arithmetic

// how much data the model sees 400M pairs × 32 epochs = 12.8 billion image–text examples 12.8B ÷ 32,768 per batch ≈ 390,000 optimiser steps // the similarity matrix is the memory problem 32,768 × 32,768 logits = 1.07 billion numbers ≈ 2.1 GB in 16-bit, before gradients // the fix: shard it (256 GPUs → 128 local pairs each) all-gather the text embeddings: 32,768 × 512 × 2 bytes ≈ 34 MB // cheap to share each GPU computes its own rows: 128 × 32,768 ≈ 4.2M logits // 256× smaller

The paper also used mixed precision, gradient checkpointing, half-precision Adam statistics and half-precision text-encoder weights to fit the encoders in memory. The largest ResNet (RN50x64) took 18 days on 592 V100 GPUs; ViT-L/14 took 12 days on 256 V100s. ViTs were about 3× more compute-efficient than ResNets for the same accuracy.

Where CLIP's knowledge comes from: WIT's 500,000 queries were built from every word appearing at least 100 times in English Wikipedia plus popular bigrams and article titles, with up to 20,000 pairs per query to balance concepts. That breadth — not a clever architecture — is why CLIP recognises far more concepts than any fixed label set.
Section 05

CLIP at Inference: Zero-Shot Classification, Retrieval and Beyond

Zero-shot classification, step by step

1

Write labels as sentences

“a photo of a driver using a phone”, “a photo of a driver eating”, “a photo of a driver looking at the road”.

2

Encode the labels once

Text encoder → 3 normalised vectors. Cache them; they never change.

3

Encode the image

Image encoder → 1 normalised vector per dashcam frame.

4

Compare and softmax

Cosine with each label × 100 (the learned logit scale), then softmax.

// Illustrative numbers for one dashcam frame (CLIP cosine similarities are typically 0.2–0.35) cos(frame, "…using a phone") = 0.31 → × 100 = 31 cos(frame, "…eating") = 0.24 → × 100 = 24 cos(frame, "…looking at the road") = 0.27 → × 100 = 27 softmax([31, 24, 27]) = [0.981, 0.001, 0.018] → prediction: using a phone // A 0.04 gap in cosine becomes a 98% decision because of the ×100 scale learned in training.

Zero-shot classification is a linear classifier written in English

Stack the K normalised label embeddings as the rows of a matrix W (K × 512). Then the whole zero-shot classifier is one line:

probabilities = softmax( 100 · W · x ) // x = normalised image embedding (512) // This is exactly a linear (logistic-regression) classifier with no bias. // The difference: its weights W were not learned from labelled images — // the text encoder WROTE them from the class names.

This is why the CLIP paper describes the text encoder as a hypernetwork: a network that produces the weights of another model. Changing the label set changes the classifier instantly, with no training.

Prompt engineering and ensembling (a real, measured effect)

A bare class name is ambiguous (“crane” the bird or the machine?) and unlike the captions CLIP saw. The paper measured that the template "A photo of a {label}." improved ImageNet accuracy by 1.3 points, and averaging the text embeddings of 80 templates (“a blurry photo of a {}”, “a sketch of a {}”, …) added 3.5 more — almost 5 points in total, for free at inference.

// prompt ensembling for class c with K templates (CLIP used K = 80 for ImageNet) w_c = normalise( (1/K) · Σ_k normalise( text_encoder( template_k(c) ) ) ) // computed ONCE per class and cached → zero extra cost per image // e.g. "a photo of a dog." · "a blurry photo of a dog." · "a sketch of a dog." · "a close-up photo of a dog."

What zero-shot CLIP is good and bad at (from the paper)

StrongWeak
General object categories (ImageNet 76.2%), action recognition, OCR of large text, geo-localisation, robustness to distribution shift: on ImageNet variants such as sketches, renditions and ObjectNet, zero-shot CLIP closes up to ~75% of the robustness gap of supervised ImageNet models. Counting objects, precise spatial relations, fine-grained or specialised domains (satellite imagery, medical images, tumour detection), and abstract tasks. Zero-shot MNIST digits: about 88% — worse than simple logistic regression on raw pixels, because handwritten digits are rare in web image–caption data.

Other uses of the same embeddings (retrieval systems, data filtering, CLIPScore, conditioning image generators, and the eyes of VLMs) are covered in §09.

Real failure: the typographic attack. OpenAI researchers studying CLIP's “multimodal neurons” (Goh et al., 2021) showed that a Granny Smith apple with a handwritten paper label reading “iPod” was classified as an iPod. CLIP learned to read text in images so well that written words can override what the object looks like. The same weakness reappears in VLMs as prompt injection through images (text in a picture that instructs the model).
Section 06

After CLIP: ALIGN, SigLIP, and Why Data Curation Matters

ALIGN — scale beats cleanliness (Jia et al., Google, 2021)

Same dual-encoder recipe, but with 1.8 billion image–alt-text pairs and only minimal filtering, an EfficientNet image encoder and a BERT text encoder. Despite the noise, ALIGN reached zero-shot ImageNet accuracy comparable to CLIP. The lesson: with enough scale, noisy free data can substitute for expensive curation.

SigLIP — replace the softmax with a sigmoid (Zhai et al., Google, 2023)

Softmax InfoNCE needs every row normalised across the whole batch, which forces a global all-gather of the N × N matrix. SigLIP treats every cell as an independent binary question: is this a matching pair, yes or no?

// z_ij = +1 on the diagonal (match), −1 everywhere else; t and b are learned (init t = 10, b = −10) L = −(1/N) Σ_i Σ_j log σ( z_ij · ( t · x_i·y_j + b ) ) // worked cells at initialisation (t = 10, b = −10): matching pair, cos 0.9: σ(+1·(9 − 10)) = σ(−1) → loss 1.313 // still pushed up mismatched pair, cos 0.1: σ(−1·(1 − 10)) = σ(+9) → loss 0.0001 mismatched pair, cos 0.2: σ(−1·(2 − 10)) = σ(+8) → loss 0.0003 // the strongly negative bias b reflects that almost every cell is a negative pair
Softmax (CLIP)Sigmoid (SigLIP)
Each cell is…one option in an N-way choice per row/columnan independent yes/no decision

SigLIP's So400m/14 encoder became the default vision tower for many 2024–25 VLMs (PaliGemma, and many open LLaVA-style models).

Open reproductions and the data lesson

  • OpenCLIP + LAION-5B (2022): open training code and 5.85 billion CLIP-filtered pairs; reproduced and exceeded CLIP and established scaling laws for contrastive models.
  • DataComp (2023) and MetaCLIP (2023): holding the model fixed and changing only the data selection produced large gains — curation (balancing concepts, removing near-duplicates and junk) matters as much as scale.
Exam-ready summary: CLIP = softmax contrastive, curated 400M; ALIGN = same idea, noisy 1.8B; SigLIP = sigmoid loss, memory-efficient, strong at small batch. All three are dual encoders: great for retrieval and classification, unable to generate text.
Section 07

The Geometry of the Shared Space

The modality gap

Liang et al. (2022) found that CLIP's image embeddings and text embeddings occupy two separate narrow cones of the sphere rather than intermixing. A matching image and caption are closer to each other than to non-matching items, but their absolute cosine similarity is modest — often around 0.3, not near 1.0.

Practical consequence: never threshold CLIP scores as if 0.3 meant “30% match”. Use relative ranking (which caption scores highest), or calibrate a threshold on your own data. This is also why the ×100 logit scale exists.
// measuring the modality gap Δ = mean( image embeddings ) − mean( text embeddings ) // one vector; ‖Δ‖ is clearly non-zero in CLIP // Liang et al. traced it to two causes: (1) at random initialisation each encoder already maps // its inputs into a narrow cone; (2) the contrastive loss at low temperature preserves that gap. // Shifting all embeddings along Δ changes zero-shot accuracy and fairness metrics.

Bag-of-words behaviour

Because the contrastive task can usually be solved by noticing which objects are present, CLIP-style models often ignore how they are related.

  • Winoground (Thrush et al., 2022): pairs like “a mug in some grass” vs “some grass in a mug” — same words, different meaning. CLIP and other contemporary models scored at or below chance.
  • ARO benchmark (Yuksekgonul et al., 2023): “the horse is eating the grass” vs “the grass is eating the horse” — models frequently preferred the wrong order. The authors called this behaving like a bag of words, and showed that training with hard negatives (captions with swapped word order) partly fixes it (NegCLIP).

Cross-modal arithmetic

Because both modalities share one space, you can query across them: text→image (search), image→text (zero-shot labels, caption ranking), image→image (visual similarity). Every downstream system in Part 4 is one of these three queries on top of the same embeddings.

// Linear probe: ordinary logistic regression on frozen features x = f(image) p(class | x) = softmax( A x + b ) // only A and b are learned // CoOp: learn the prompt's words as vectors instead of writing them prompt for class c = [v_1] [v_2] … [v_M] [embedding of "c"] // v_1…v_M trained, encoders frozen // WiSE-FT: interpolate the weights of the zero-shot and the fine-tuned model θ_α = (1 − α) · θ_zero-shot + α · θ_fine-tuned // α ≈ 0.5 keeps most of the in-domain gain // and recovers much of the robustness
Decision guide: no labels → zero-shot with prompt ensembling. 1–16 labels per class → CoOp, CLIP-Adapter or a linear probe. Thousands of labels → fine-tune, then WiSE-FT to keep robustness. Always compare against the zero-shot baseline: it is free and often surprisingly hard to beat.

CLIP's embeddings are reused far beyond classification. Five uses cover most of what you will meet.

Every use inherits CLIP's weaknesses. If CLIP treats “a mug in the grass” and “grass in a mug” alike (§07), a CLIP-filtered dataset, a CLIPScore metric and a CLIP-conditioned generator will all share that blind spot. This is one reason image generators struggled with spatial prompts and counting.

Hands-On Code (Hugging Face Transformers)

CLIP zero-shot classification

import torch from PIL import Image from transformers import CLIPModel, CLIPProcessor model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32") processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32") image = Image.open("dashcam_frame.jpg") labels = ["a photo of a driver using a phone", "a photo of a driver eating", "a photo of a driver looking at the road"] inputs = processor(text=labels, images=image, return_tensors="pt", padding=True) with torch.no_grad(): out = model(**inputs) probs = out.logits_per_image.softmax(dim=1) # logits already include the learned ×100 scale print(dict(zip(labels, probs[0].tolist())))

The CLIP loss in PyTorch (what you would train)

import torch, torch.nn.functional as F def clip_loss(img_emb, txt_emb, logit_scale): img_emb = F.normalize(img_emb, dim=-1) # [N, d] txt_emb = F.normalize(txt_emb, dim=-1) # [N, d] logits = logit_scale.exp() * img_emb @ txt_emb.t() # [N, N] labels = torch.arange(len(logits), device=logits.device) return (F.cross_entropy(logits, labels) + F.cross_entropy(logits.t(), labels)) / 2 # logit_scale = nn.Parameter(torch.tensor(math.log(1 / 0.07))); clamp it to log(100) after each step

Prompt ensembling (§05) in a few lines

templates = ["a photo of a {}.", "a blurry photo of a {}.", "a sketch of a {}.", "a close-up photo of a {}."] classes = ["dog", "cat", "car"] with torch.no_grad(): W = [] for c in classes: t = processor(text=[tp.format(c) for tp in templates], return_tensors="pt", padding=True) e = model.get_text_features(**t) e = e / e.norm(dim=-1, keepdim=True) # normalise each template m = e.mean(dim=0) W.append(m / m.norm()) # average, then normalise again W = torch.stack(W) # [num_classes, 512] = the classifier weights x = model.get_image_features(**processor(images=image, return_tensors="pt")) x = x / x.norm(dim=-1, keepdim=True) probs = (model.logit_scale.exp() * x @ W.T).softmax(dim=-1)

Text-to-image search with FAISS

import faiss, numpy as np # gallery: N images → normalised CLIP image embeddings, float32 [N, 512] index = faiss.IndexFlatIP(512) # inner product = cosine, because vectors are normalised index.add(gallery_emb) q = model.get_text_features(**processor(text=["a dog carrying a ball"], return_tensors="pt", padding=True)) q = (q / q.norm(dim=-1, keepdim=True)).detach().numpy().astype("float32") scores, ids = index.search(q, 5) # top-5 images

Section 11

Key Takeaways & Exam Prep

✓

Alignment = one shared coordinate system

Train both encoders so matching image and text vectors are close.

✓

Images become tokens

ViT: (side / patch)² patch tokens; 336px with 14px patches = 576.

✓

Contrastive = N-way classification

Symmetric InfoNCE; the gradient pulls to the true pair and pushes hardest on confusable negatives.

✓

τ and N set the difficulty

Low τ sharpens; large N gives more near-misses; initial loss ≈ ln N.

✓

Zero-shot = a linear classifier from text

The text encoder writes the classifier's weights from class names.

Common exam questions

QuestionShort answer
What does “multimodal alignment” mean?Training an image encoder and a text encoder so they share one embedding space, in which matching images and texts have high cosine similarity and non-matching ones low
How many visual tokens does a ViT-L/14 produce for a 336×336 image?(336/14)² = 24² = 576 patch tokens (+1 CLS)
Why does a ViT need position embeddings?Self-attention is permutation-invariant; without positions, shuffled patches would give the same output
Write CLIP's loss and explain each term.Symmetric cross-entropy over the cosine-similarity matrix scaled by 1/τ; rows classify texts for each image, columns images for each text; the diagonal is the label
What is the gradient of the InfoNCE row loss with respect to a logit, and what does it do?p_ij − 1[j = i]. It raises the true pair's score and lowers each negative in proportion to its current probability, so confusable (hard) negatives are pushed hardest
What happens to the loss if τ is lowered from 1 to 0.1 for the same embeddings?Logits are multiplied by 10, the softmax sharpens, and the loss on correctly ranked pairs collapses (0.744 → 0.011 in the worked example); gradients concentrate on hard negatives
What loss should a freshly initialised CLIP show with batch size N, and why?About ln N (≈ 10.4 for N = 32,768), because all similarities are roughly equal so each p_ij ≈ 1/N
Why does a larger batch help contrastive learning?More negatives per example, including near-misses, which forces fine-grained features; the InfoNCE mutual-information bound log N − L also grows with N
Why is the 32,768 × 32,768 similarity matrix not a problem in practice?It is sharded: each GPU gathers all text embeddings (small) and computes only its own rows
How does CLIP do zero-shot classification, and why is it a linear classifier?Embed each label as a sentence and pick the highest cosine with the image; the stacked label embeddings act as the weight matrix of a bias-free linear classifier
Why does SigLIP work with smaller batches than CLIP?Each pair is an independent sigmoid decision, so there is no global softmax normalisation across the batch
You have 8 labelled images per class. How would you adapt CLIP?Prompt learning (CoOp) or a lightweight adapter / linear probe, compared against the zero-shot baseline
What does WiSE-FT do?Averages the weights of the zero-shot and fine-tuned models, θ = (1 − α)θ_zs + αθ_ft, keeping most of the fine-tuning gain while recovering robustness to distribution shift
What is CLIPScore?2.5 · max(cos(image, text), 0): a reference-free score of how well a caption or prompt matches an image
