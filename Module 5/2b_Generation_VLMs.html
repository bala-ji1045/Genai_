Section 01

From Alignment to Vision-Language Models: Four Ways to Wire Vision into an LLM

Part 2a built the aligned vision encoder: CLIP turns an image into vectors that sit next to the matching text (alignment), and a ViT turns the image into a sequence of patch tokens (Part 2a §02). This Part answers the next question: how do we get a model that can talk about the image? Part 1 §04 gave a one-card overview of each technique; here each model is covered in full.

A dual encoder can score an image–text pair but cannot write text. To answer “What is unusual about this image?”, we need a language model that can condition on the image. There are four ways to connect them:

FIG 3 — The four connection patterns. Most open VLMs since 2023 use pattern C because it is the simplest to train and reuses existing LLMs unchanged.
PatternHow the LLM sees the imageVisual tokensWhat is trainedStrengthWeakness
A · Cross-attentionNew cross-attention layers inside the LLM read image featuresNot in the sequence (no context cost)New cross-attention layers (+ resampler)Keeps the LLM's text skills intact; many images cheapChanges the LLM architecture
B · Query bridgeA small Transformer distils the image into a few query vectors, fed as soft promptFixed and small (32–64)Only the bridge (~100–200M params)Very cheap to train; short sequencesCompression loses fine detail (OCR, small objects)
C · Projected tokensEvery patch feature becomes a token in the LLM's inputMany (256, 576, up to thousands)Projector, then projector + LLMSimple, strong, keeps detailLong sequences: cost grows with resolution
D · NativeAll modalities tokenised into one sequence from pretrainingVariesEverything, from scratchBest cross-modal reasoning; can also output images/audioOnly feasible for frontier labs
Section 02

Flamingo: Few-Shot Learning Across Images and Text

Flamingo (Alayrac et al., DeepMind, 2022) — pattern A
VisionNFNet-F6, contrastively pretrained, then frozen
LanguageFrozen Chinchilla LMs (1.4B, 7B, 70B) → Flamingo-3B / 9B / 80B
New partsPerceiver Resampler + gated cross-attention (XATTN-DENSE) layers
DataM3W: 43M web pages with interleaved images and text; ALIGN (1.8B pairs); LTIP (312M pairs); VTP (27M short videos)
Signature skillIn-context few-shot learning with interleaved images, like GPT-3 prompting

Architecture

  1. Perceiver Resampler. The vision encoder outputs a variable number of features (more for higher resolution or more video frames). A fixed set of 64 learned latent queries cross-attends to them and outputs exactly 64 visual tokens per image — a constant-size summary. For video, features from frames (with learned time embeddings) are resampled together.
  2. Gated XATTN-DENSE layers. Inserted between the frozen LM layers. Each one lets text tokens cross-attend to the visual tokens, followed by a feed-forward layer. Its output is multiplied by tanh(α), where α is a learned scalar initialised to 0 — so at the start of training the model is exactly the original language model, and vision is blended in gradually. This protects the LM's language ability.
  3. Image-causal masking. In an interleaved document, each text token attends only to the image that immediately precedes it, while the LM's self-attention still sees all previous text. This lets one sequence contain many images.

Training

Only the resampler and the cross-attention layers are trained; vision encoder and LM stay frozen. The objective is ordinary next-token prediction on text, conditioned on the interleaved images, with a weighted mixture of the four datasets. The interleaved web pages (M3W) are what give Flamingo its in-context ability: it learned from documents where images and text naturally alternate.

Inference: few-shot prompting with images

# A 2-shot prompt (images shown as <image>) <image: flamingo photo> Output: This is a flamingo. They are found in the Caribbean. <image: panda photo> Output: This is a panda. They are found in China. <image: new photo> Output: ← the model continues in the same style

Result: with a handful of examples and no fine-tuning, Flamingo-80B set a new few-shot state of the art on 16 image and video benchmarks, and on 6 of them beat models fine-tuned on thousands of times more task data. Open reproductions: OpenFlamingo and Hugging Face's IDEFICS.

Section 03

BLIP-2: Bridging Frozen Models with a Q-Former

BLIP-2 (Li et al., Salesforce, 2023) — pattern B
VisionFrozen ViT-g/14 from EVA-CLIP
LanguageFrozen OPT (2.7B, 6.7B) or Flan-T5 (XL, XXL)
BridgeQ-Former: ~188M params, 32 learned query vectors of size 768, initialised from BERT-base
Data129M images (COCO, Visual Genome, CC3M, CC12M, SBU, 115M from LAION) with synthetic captions (CapFilt)
HeadlineBeat Flamingo-80B by 8.7 points on zero-shot VQAv2 with 54× fewer trainable parameters

The Q-Former

A small Transformer with two inputs: 32 learnable query embeddings and text. The queries cross-attend to the frozen image features (in every other block) and interact with the text through shared self-attention layers. Whatever the image looks like, the output is 32 vectors — a learned “interview” of the image.

Two-stage training

StageConnected toLossesWhat it teaches
1 · Representation learningFrozen image encoder only ITC image–text contrastive (queries vs text CLS);
ITM image–text matching, a binary classifier with hard negatives;
ITG image-grounded text generation (text generated from the queries)		 Make the 32 queries extract the visual information most relevant to text. Each loss uses a different self-attention mask between queries and text.
2 · Generative learningFrozen image encoder + frozen LLM Language-modelling loss (decoder LLM) or prefix-LM loss (Flan-T5) A linear layer maps the 32 query outputs to the LLM's embedding size; they are prepended to the text as “soft visual prompts”.

Inference

image (224×224) → frozen ViT-g → 257 × 1408 features → Q-Former (32 queries) → 32 × 768 → linear → 32 × 2560 (OPT-2.7B width) → [32 visual tokens] + "Question: how many dogs are in the picture? Answer:" → LLM → "two"
Why it mattered: BLIP-2 showed you could build a capable VLM by training only a small bridge between two frozen, off-the-shelf models. InstructBLIP (2023) added instruction-aware queries (the instruction is also fed into the Q-Former) and instruction tuning across 26 datasets. The trade-off is compression: 32 tokens struggle with dense text and small details, which is why later models moved to pattern C.
Section 04

LLaVA: Visual Instruction Tuning, End to End

LLaVA — Large Language and Vision Assistant (Liu et al., NeurIPS 2023) and LLaVA-1.5 (2023) — pattern C
VisionCLIP ViT-L/14 (224px in v1, 336px in 1.5), frozen; features from the second-to-last layer
Connectorv1: one linear layer · 1.5: two-layer MLP with GELU
LanguageVicuna (LLaMA fine-tuned on conversations), 7B and 13B
Key ideaUse a text-only GPT-4 to write multimodal instruction data
Cost (1.5-13B)About one day on a single 8×A100 node
FIG 4 — LLaVA-1.5-13B. For the 7B model the projector outputs width 4096 instead of 5120.

The data trick: GPT-4 writes the training data

In 2023 there was little multimodal instruction data. LLaVA's authors gave a text-only GPT-4 a symbolic description of COCO images — the five human captions plus the object bounding boxes — and asked it to write three kinds of data:

TypeCountExample of what GPT-4 wrote
Conversations58KMulti-turn Q&A as if looking at the image: “What colour is the bus?” → “The bus is red and white.”
Detailed descriptions23KA rich paragraph describing everything in the scene.
Complex reasoning77K“What challenges might these people face?” — answers that require inference beyond what is visible.
Total (LLaVA-Instruct-158K)158KGPT-4 never saw a pixel — it reasoned from the captions and boxes.

Two-stage training

StageDataTrainedFrozenPurpose
1 · Feature alignmentv1: 595K filtered CC3M pairs · 1.5: 558K LAION/CC/SBU pairs with BLIP captions — each turned into “Describe this image briefly.” → captionProjector onlyViT + LLMTeach the projector to translate CLIP features into vectors the LLM understands — like learning a visual “dictionary”.
2 · Visual instruction tuningv1: 158K instructions (+ ScienceQA) · 1.5: 665K mix — LLaVA-Instruct, ShareGPT text conversations, VQAv2, GQA, OKVQA, OCR-VQA, A-OKVQA, TextCaps, RefCOCO, Visual GenomeProjector + LLMViTTeach the model to follow instructions about images and answer in the right format.
// Loss: standard next-token cross-entropy, computed ONLY on the assistant's answer tokens L = −Σ_t log p( answer_t | image tokens, instruction, answer_<t ) // The image tokens and the user's question are context, never prediction targets.
LLaVA-1.5's small fix with a big effect: academic VQA datasets have one-word answers, which made the model terse everywhere. LLaVA-1.5 appended a format prompt to those examples — “Answer the question using a single word or phrase.” — so the model learned when to be short. Together with the MLP projector and 336px input, LLaVA-1.5 reached state of the art on 11 of 12 benchmarks it reported, using only public data.

Inference walk-through with a real example

The LLaVA paper (following the GPT-4 report) used a photo of a man ironing clothes on an ironing board attached to the back of a moving yellow taxi in a city street.

  1. Pre-process: resize/pad to 336×336, normalise with CLIP's mean and std.
  2. Encode: ViT-L/14 → 24×24 = 576 patch features from the penultimate layer, each 1024-d.
  3. Project: MLP → 576 vectors of LLM width.
  4. Build the prompt: USER: <image>\nWhat is unusual about this image? ASSISTANT: — the placeholder becomes the 576 vectors.
  5. Prefill: the LLM processes all ~600 input positions in one pass and fills its KV cache (Module 1).
  6. Decode: generate token by token: the man is ironing clothes on an ironing board attached to the roof of a moving taxi, which is unusual and unsafe…

LLaVA-NeXT (LLaVA-1.6, 2024): AnyRes

To read small text, the input image is split into a grid of 336×336 tiles (for example 672×672 → 2×2 tiles) plus one downsampled global view; each tile is encoded separately and the tokens concatenated — up to roughly 2,880 visual tokens. Better OCR and detail, at the cost of a much longer sequence.

Modern Open VLMs: Qwen2-VL, PaliGemma and Llama 3.2 Vision

Qwen2-VL (Alibaba, 2024) — pattern C with dynamic resolution
Vision~675M-param ViT with 2D rotary position embeddings, trained to accept any resolution
Token mergingEach 2×2 block of 14px patches is merged by an MLP into one token
PositionsM-RoPE: rotary positions split into temporal, height and width components
Sizes2B, 7B, 72B
// Naive Dynamic Resolution: no fixed input size, no tiling 224×224 image → 16×16 patches of 14px → merge 2×2 → 8×8 = 64 tokens (+ vision start/end markers) 896×672 image → 64×48 patches → merge 2×2 → 32×24 = 768 tokens // Token count follows the image's real size and aspect ratio. Video: frames sampled (e.g. 2 per second), // and M-RoPE's time axis tells the model which frame each token came from.
PaliGemma (Google, 2024) — pattern C with a prefix-LM
VisionSigLIP So400m/14
LanguageGemma-2B
Image tokens256 at 224px · 1,024 at 448px · 4,096 at 896px
AttentionFull (bidirectional) over image + prompt (“prefix”); causal over the answer (“suffix”)

PaliGemma is designed as a transferable base rather than a chatbot. Its prompts are task prefixes, and its vocabulary includes 1,024 location tokens (<loc0000>…<loc1023>) and segmentation tokens, so detection and segmentation become text generation:

prefix: "detect car" → suffix: "<loc0123><loc0456><loc0789><loc0890> car" // four location tokens = a bounding box (y_min, x_min, y_max, x_max) on a 1024-step grid prefix: "caption en" → suffix: "a white truck parked beside a loading dock" prefix: "answer en what colour is the truck?" → "white"

Training: unimodal pretraining of each component, multimodal pretraining with all parameters unfrozen, a resolution-increase stage, then per-task transfer (fine-tuning).

Llama 3.2 Vision (Meta, 2024) — pattern A
Sizes11B and 90B
DesignAn image encoder plus cross-attention adapter layers feeding image representations into the Llama 3.1 language model
TrainingAdapters trained on image–text data while the language-model weights were kept frozen, preserving text-only behaviour
Why Meta chose cross-attention: it keeps the text model identical (a drop-in replacement for Llama 3.1 on text tasks) and keeps visual tokens out of the context window. LLaVA-style models instead fine-tune the LLM, which can slightly degrade pure-text skills unless text-only data is mixed in (LLaVA-1.5 added ShareGPT conversations for exactly this reason).

Natively Multimodal Models: GPT-4V, Gemini, GPT-4o, Chameleon

ModelWhat is public about the architectureNotable capabilities
GPT-4V (OpenAI, Sep 2023)Vision added to GPT-4; architecture and data undisclosed (system card only)Strong general visual reasoning, charts, documents; API access only
Gemini 1.0 (Google DeepMind, Dec 2023)Transformer decoder trained from the start on interleaved text, images, audio and video; can output images through discrete image tokensVideo as sequences of frames; audio understanding; multilingual
Gemini 1.5 (2024)Mixture-of-experts; context up to 1M tokens (later 2M)Reasoning over roughly an hour of video or very long documents in one prompt
GPT-4o (OpenAI, May 2024)One model trained end to end across text, vision and audio (“o” for omni)Speech in, speech out without a separate speech-to-text step; average voice response latency around 320 ms
Chameleon (Meta, 2024)Early fusion: images converted to discrete tokens by a learned image tokenizer (VQ), mixed with text tokens in one vocabularyReads and generates interleaved image-and-text documents
Bolt-on vs native, the trade-off in one line: bolting vision onto a pretrained LLM (LLaVA) is cheap and reuses everything; training on all modalities from scratch (Gemini, GPT-4o) lets cross-modal reasoning emerge in pretraining and enables generating non-text outputs, but costs a frontier-scale training run. This is Module 1's “pretrain once, adapt cheaply” trade-off, applied across modalities.

The common pattern in almost every open VLM: (1) start from a contrastively aligned vision encoder; (2) align: train only the connector on image–caption pairs; (3) instruction-tune: train connector + LLM on instruction data; (4) optionally preference-tune (RLHF or DPO) to reduce hallucination and improve helpfulness.

Hands-On Code (Hugging Face Transformers)

CLIP code (zero-shot classification, the loss, retrieval) is in Part 2a §10. The two examples below run a frozen-bridge VLM (BLIP-2) and a projected-token VLM (LLaVA-1.5) on the same image.

import torch from PIL import Image image = Image.open("your_photo.jpg")

BLIP-2 visual question answering

from transformers import Blip2Processor, Blip2ForConditionalGeneration processor = Blip2Processor.from_pretrained("Salesforce/blip2-opt-2.7b") model = Blip2ForConditionalGeneration.from_pretrained( "Salesforce/blip2-opt-2.7b", torch_dtype=torch.float16, device_map="auto") inputs = processor(images=image, text="Question: how many people are in the picture? Answer:", return_tensors="pt").to(model.device, torch.float16) print(processor.decode(model.generate(**inputs, max_new_tokens=20)[0], skip_special_tokens=True))

LLaVA-1.5 chat

from transformers import AutoProcessor, LlavaForConditionalGeneration model_id = "llava-hf/llava-1.5-7b-hf" model = LlavaForConditionalGeneration.from_pretrained(model_id, torch_dtype=torch.float16, device_map="auto") processor = AutoProcessor.from_pretrained(model_id) prompt = "USER: <image>\nWhat is unusual about this image? ASSISTANT:" inputs = processor(images=image, text=prompt, return_tensors="pt").to(model.device, torch.float16) out = model.generate(**inputs, max_new_tokens=120) print(processor.decode(out[0], skip_special_tokens=True)) # print(inputs["input_ids"].shape) shows the sequence length including the 576 image positions

Section 09

Key Takeaways & Exam Prep

✓

Score vs generate

A dual encoder (CLIP) scores image–text pairs; a VLM writes text conditioned on the image.

✓

Four ways to wire vision into an LLM

Cross-attention, query bridge, projected tokens, native.

✓

Align, then instruction-tune

The two-stage recipe behind LLaVA and most open VLMs.

✓

Token budget is the trade-off

32–64 tokens (BLIP-2, Flamingo) are cheap but lose detail; 576+ (LLaVA, Qwen2-VL) keep detail but cost more.

Common exam questions

QuestionShort answer
Why can't CLIP answer “What is unusual about this image?”It is a dual encoder: it outputs embeddings and a similarity score, with no decoder to generate text. Answering needs a language model conditioned on the image (a VLM)
What is the Perceiver Resampler and why does Flamingo need it?Learned latent queries that cross-attend to a variable number of visual features and output a fixed 64 tokens, so any resolution or number of frames costs the same downstream
Why is Flamingo's gate initialised to zero?tanh(0) = 0, so the model starts as the unchanged language model and vision is blended in gradually, protecting language ability
Name BLIP-2's stage-1 losses.Image-text contrastive (ITC), image-text matching (ITM), image-grounded text generation (ITG)
Describe LLaVA's two training stages.Stage 1: train only the projector on image–caption pairs (feature alignment). Stage 2: train projector + LLM on visual instruction data; the vision encoder stays frozen
How was LLaVA's instruction data created?A text-only GPT-4 was given COCO captions and bounding boxes and wrote 158K conversations, detailed descriptions and reasoning questions
Bolt-on (LLaVA) vs native (Gemini)?Bolt-on reuses a pretrained LLM and trains a connector cheaply; native trains one model on all modalities from scratch, with stronger cross-modal reasoning and the ability to output other modalities, at far higher cost
Why did BLIP-2 struggle with dense text compared with LLaVA-1.5?BLIP-2 compresses every image into 32 query vectors; LLaVA-1.5 passes all 576 patch tokens from a 336px image, keeping much more fine detail
