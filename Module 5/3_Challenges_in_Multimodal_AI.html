Section 01

Data Availability

Text-only LLM pretraining (Module 1 §01) draws on an enormous, relatively easy-to-collect corpus: the open web's text. Paired multimodal data is scarcer and lower quality by comparison.

Data needAvailability
Raw imagesAbundant
Images paired with accurate, detailed textMuch scarcer — most web images have short, generic, or missing alt-text
Domain-specific pairs (medical scans + reports, technical diagrams + captions)Scarce and often privacy-restricted or proprietary
Non-English / low-resource-language image-text pairsSeverely underrepresented relative to English
Why this specifically limits fine-grained visual understanding: a model can learn "this is a dog" from millions of loosely-captioned dog photos, but learning to reliably answer "is the dog's left ear torn?" needs images paired with that level of detail in the text — data that's dramatically rarer. General object recognition saturates faster than fine-grained visual question answering, purely because of what data exists.
Section 02

Alignment Complexity, Revisited

Module 5 Part 2a §07 showed alignment problems at the embedding level (the modality gap, Winoground and ARO results) and §05 the typographic attack. At the full vision-language-model level (Part 2b §01–§06), the same underlying problem — text and vision carry information at different granularities — resurfaces as harder failure modes.

Failure modeRoot cause
Missing fine detail in generated descriptionsTraining captions were themselves coarse (Part 1 §01) — the model learned to describe at that same coarse level
Spatial relationship errors ("the cup is on the left" when it's on the right)Contrastive training (Part 2a §03) optimizes whole-image-to-whole-caption similarity, with no explicit supervision for fine spatial relationships
Poor compositional generalizationRare attribute-object combinations in training data (Part 2a §07) — the model has seen "red car" and "blue truck" separately far more than "blue car"
Noisy web pairsAlt-text is often generic, wrong or unrelated to the image; scale partly compensates (ALIGN, Part 2a §06), but curation still gives large gains (DataComp, MetaCLIP)
Reading beats seeingText inside an image is a strong, easy signal, so written words can override the object itself (the “iPod” apple, Part 2a §05) — the root of prompt injection through images
Section 03

Hallucinations — the Multimodal Version

Module 2 discussed hallucination implicitly (grounding via ReAct, Module 2 §04). In vision-language models, hallucination takes a specific, well-studied form: the model confidently describes objects, attributes, or relationships that are not present in the image.

FIG 1 — A classic hallucination pattern: apples and kitchen counters co-occur frequently with bananas and coffee mugs in training data, so the model's language-generation prior "fills in" statistically common companions rather than being fully constrained by what's actually visible.
CauseWhy it produces hallucination
Language prior overriding visual evidenceThe text-generation side of a VLM (often a large pretrained LLM, Part 2b §01) has strong statistical expectations about what co-occurs — "kitchen counter" strongly predicts "coffee mug" in text, independent of this specific image
Coarse training captions (§01/§02)If training captions rarely enumerate everything absent, the model never learned to reliably signal absence
Ambiguous or low-resolution visual inputWhen the vision encoder's signal is genuinely weak, the language model's prior fills the gap with a plausible guess
Exam favourite: "Why are VLMs specifically prone to object hallucination, more than text-only LLMs are prone to factual hallucination?" — because a VLM has two competing sources of "truth": the actual visual input, and the language model's learned statistical priors about what typically co-occurs in captions. When the two disagree, the more confidently-trained language prior often wins, unlike a text-only LLM which only ever has one signal (its training distribution) to draw from.

How hallucination is measured

  • CHAIR (Rohrbach et al., 2018): the fraction of objects mentioned in generated captions that are not in the image's annotations.
  • POPE (Li et al., 2023): asks yes/no questions “Is there a <object> in the image?” with negatives sampled randomly, from frequent objects, or from objects that commonly co-occur with what is present (“adversarial”). Models do worst on the co-occurrence setting — direct evidence that the language prior causes hallucination.

Mitigations, from cheapest to most involved

  1. Higher resolution and better grounding data — the model hallucinates less when it can actually see the detail.
  2. Instruction data that includes “not present” answers, so the model learns to say no.
  3. Preference tuning: LLaVA-RLHF (Sun et al., 2023) used RLHF with a reward model given extra factual information (“factually augmented RLHF”); RLHF-V (Yu et al., 2023) used fine-grained human corrections of hallucinated segments with a DPO-style objective. (How preference tuning works: Part 1 §04, FIG 7.)
  4. Decoding-time fixes: Visual Contrastive Decoding (Leng et al., 2024) compares the model's next-token probabilities on the real image and on a distorted version, and down-weights tokens the language prior would produce anyway.
  5. System design: cross-check captions with an object detector, and ask the model to say when it is unsure (Part 4 §06).
Section 04

Evaluation Challenges

Module 3 §08 defined RAG evaluation metrics with well-established ground truth (a gold document). Multimodal evaluation is harder precisely because "correct" is often less binary — describing an image well admits many valid phrasings, and ground truth itself is expensive to produce.

TaskEvaluation difficulty
Image captioningMany valid captions exist for one image; automatic metrics (BLEU, CIDEr) correlate imperfectly with human judgment of quality
Visual question answeringOpen-ended answers are hard to score automatically without exact-match being overly strict
Object hallucination (§03)Requires exhaustively verifying every claim against the actual image — expensive to do at scale, and easy to under-detect
Document/OCR-heavy tasks (Module 5 Part 4)Small layout misreads compound — a shifted table column can silently corrupt every downstream number

The standard benchmarks

CapabilityBenchmarkMetric
Zero-shot classificationImageNet and its shifted variantsTop-1 accuracy
RetrievalMS-COCO, Flickr30KRecall@K (Module 3)
General visual QAVQAv2, GQA, OK-VQAVQA accuracy (agreement with 10 human answers)
Text in imagesTextVQA, DocVQA, ChartQA, OCRBenchAccuracy / ANLS
Expert multi-discipline reasoningMMMUAccuracy on college-level questions with diagrams
Broad skillsMMBench, SEED-BenchMultiple-choice accuracy
HallucinationPOPE, CHAIR (§03)F1 on yes/no; hallucinated-object rate
Open-ended chatLLaVA-BenchGPT-4-as-judge score relative to a reference answer
Read benchmark claims carefully: many VQA benchmarks can be partly solved without looking at the image (language priors), training data may overlap test images, and GPT-4-as-judge scores are relative and can favour verbose answers. Always ask: was the image necessary, was the test set clean, and who judged?
Connects directly to Module 3 §08: RAG's "faithfulness" metric (is every claim traceable to the retrieved context?) has a direct multimodal analogue: is every claim in a VLM's description traceable to something actually visible in the image? Building that checker reliably is an open, active research problem — there's no equivalent yet to RAG's relatively mature evaluation tooling.
Section 05

Compute Requirements

Images are expensive input. A single image, once patch-encoded (Module 5 Part 2a §02's ViT), can consume hundreds to thousands of "tokens" worth of sequence length — before a single word of the actual prompt is processed.

// visual tokens = (image side / patch side)² — derivation in Part 2a §02 224px, 16px patches (ViT-B/16) → (224/16)² = 196 tokens 336px, 14px patches (LLaVA-1.5) → (336/14)² = 576 tokens // Self-attention cost (Module 1 §03) is O(n² · d) in sequence length n, so the image // doesn't just add cost linearly — it inflates the QUADRATIC term every text token pays. 576 vs 196 tokens → (576/196)² ≈ 8.6× more attention compute

Cost driverPractical consequence
Image tokenization overheadEvery image inflates the effective context length substantially before any text is processed
Multi-image / video inputCost scales with the number of frames/images — a short video can dwarf a long text document in token count
High-resolution inputsMore patches per image = more tokens = more attention cost, trading fidelity against compute directly

Levers for reducing the cost

  • Prefill dominates: with hundreds of image tokens, most of the work happens before the first answer token is produced.
  • Cache the vision encoder output when asking several questions about the same image.
  • Choose resolution per task: classification and captions are fine at low resolution; documents, charts and small text need high resolution or tiling.
  • Token reduction: compress visual tokens with a query bridge (BLIP-2's 32 queries) or merge neighbouring patches (Qwen2-VL's 2×2 merge) — the main lever for speed.
  • Quantisation (4-bit or 8-bit weights, Module 1) applies to the LLM part exactly as for text models.
Why this matters for Module 5 Part 4's applications directly: a multimodal RAG or document-intelligence system processing hundreds of scanned pages has to make a deliberate resolution/cost trade-off per page — this is the same "chunk size" hyperparameter tension from Module 3 §05, now with a much steeper cost curve because image tokens are expensive in a way text tokens aren't.
Section 06

Key Takeaways & Exam Prep

✓

Paired data is the real bottleneck

Not raw images, but images paired with accurate, detailed, diverse text.

✓

Alignment errors trace back to granularity mismatch

Spatial and compositional errors are downstream of coarse training captions.

✓

Hallucination is a two-signal conflict

Language priors about what "usually" co-occurs can override actual visual evidence.

✓

Evaluation lacks RAG's maturity

Open-ended visual tasks resist the clean ground-truth Module 3's metrics rely on.

✓

Images are expensive tokens

Quadratic attention cost makes image input a much steeper compute trade-off than text.

Common exam questions

QuestionShort answer
Why are VLMs specifically prone to object hallucination?They have two competing signals — actual visual input and the language model's learned co-occurrence priors — and the language prior can override weak or ambiguous visual evidence
Why does image input cost more compute than an equivalent amount of text?Each image is tokenized into many patch-tokens (e.g. ~196 for a standard ViT patch size), and self-attention's O(n²) cost means this inflates the quadratic term substantially before any text is even processed
Why is multimodal evaluation generally harder than RAG evaluation (Module 3 §08)?Multimodal tasks like captioning and VQA are more open-ended with many valid answers, and verifying claims against an image (the multimodal analogue of "faithfulness") lacks RAG's more mature, established evaluation tooling
What does POPE measure and what does it reveal?Object hallucination via yes/no questions; models fail most on objects that co-occur with the scene, showing the language prior overriding the image
Name three ways to reduce object hallucination.Any three of: higher resolution / better grounding data; instruction data with “not present” answers; preference tuning (LLaVA-RLHF, RLHF-V); visual contrastive decoding; cross-checking with an object detector
How many visual tokens does LLaVA-1.5 use per image, and how can you reduce that cost?576 (24×24 patches at 336px); reduce by lower resolution, a query bridge, patch merging, caching encoder output for repeated questions
