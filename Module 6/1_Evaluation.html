Evaluation of GenAI Systems

How do you know if an LLM application is actually working? Hallucination detection, groundedness, BERTScore, the RAGAS framework, and why human evaluation is still the ground truth everything else is checked against.

Section 01

Hallucination Detection

Module 5 Part 3 §03 introduced hallucination in vision-language models — text-only LLMs hallucinate too, generating fluent, confident claims that are simply false. Detecting this automatically, at scale, is the first evaluation problem any production GenAI system has to solve.

Detection approachHow it worksTrade-off
Fact-checking against a knowledge sourceExtract claims, verify each against a trusted reference (a knowledge base, retrieved documents)Reliable when a reference exists; nothing to check against for open-ended generation
Self-consistency checkingSample the same query multiple times (Module 2 §04); claims that vary wildly across samples are suspectCheap, no reference needed; catches inconsistency, not confident-but-consistent falsehood
NLI-based entailment scoringA natural language inference model checks whether the source text entails the generated claimDirectly answers "is this claim supported," at the cost of another model call
LLM-as-judgePrompt a (typically stronger) LLM to assess whether a claim is supported by given contextFlexible and scalable; inherits whatever biases and blind spots the judge model has
The recurring problem across all four approaches: detecting hallucination requires something to check the claim against — a reference, other samples, an entailment model, or a judge. There is no way to verify truthfulness from the generated text alone; every detection method smuggles in an external source of ground truth, explicitly or implicitly.
Section 02

Groundedness

Module 3 §08 defined faithfulness for RAG specifically: is every claim in the answer traceable to the retrieved context? Groundedness is the same idea generalized — the degree to which a model's output is supported by whatever source material it was given, independent of whether the output happens to also be true.

// A simple groundedness check, conceptually for claim in extract_claims(generated_answer): supported = nli_model.entails(source_context, claim) // does context ENTAIL claim? if not supported: flag_as_ungrounded(claim) groundedness_score = supported_claims / total_claims
Exam favourite: "Can an answer be groundless but still correct?" — Yes, and this is precisely why groundedness is measured separately from factual accuracy. An answer can happen to be true by coincidence — drawn from the LLM's own parametric knowledge rather than the provided context — which is exactly the failure mode Module 3 §08 flagged: unfaithful but not wrong. A production system that can't distinguish these will look fine on accuracy metrics while silently not actually using its retrieval step.
Section 03

BERTScore

Comparing a generated answer to a reference answer word-for-word (like classic n-gram metrics such as BLEU) penalizes paraphrase heavily — "the cat sat on the mat" and "a feline rested on the rug" mean nearly the same thing but share almost no words. BERTScore (Zhang et al., 2019) compares meaning instead, using contextual embeddings (Module 1 §03's embeddings, from a BERT-style encoder) rather than exact token overlap.

// BERTScore, conceptually — for each token in the candidate, find its best-matching // token (by embedding cosine similarity) in the reference, and vice versa Precision = avg over candidate tokens of max cosine similarity to any reference token Recall = avg over reference tokens of max cosine similarity to any candidate token F1 = 2 · Precision · Recall / (Precision + Recall) // Unlike BLEU's exact n-gram matching, two tokens with different surface forms but // similar embeddings ("rested" <-> "sat") still contribute a high similarity score.
MetricMatches onHandles paraphrase?
BLEU / ROUGE (n-gram overlap)Exact word/phrase sequencesPoorly — different wording scores low even if correct
BERTScoreContextual embedding similarity per tokenWell — captures near-synonymous phrasing
Where this connects back: BERTScore is doing, at the token level, exactly what Module 3 §01's cosine similarity does at the sentence/document level — the same "compare meaning via embedding distance, not surface text" idea, just applied to scoring generated text against a reference instead of to retrieval.
Section 04

RAGAS

RAGAS (RAG Assessment, Es et al., 2023) is a framework purpose-built for evaluating RAG pipelines (Module 3) — it doesn't invent new individual metrics so much as it formalizes and automates the exact evaluation layers Module 3 §08 introduced, computing them with an LLM-as-judge (SS01) rather than needing hand-labeled ground truth for every query.

RAGAS metricWhat it measuresMaps to Module 3 §08's...
FaithfulnessFraction of claims in the answer supported by retrieved contextGroundedness (SS02)
Answer relevanceDoes the answer actually address the question asked?Answer relevance
Context precisionOf the retrieved chunks, how many were actually relevant?Context precision
Context recallOf the chunks that were needed, how many were actually retrieved?Context recall
// RAGAS faithfulness, conceptually — this IS SS01's hallucination detection, // applied specifically to a RAG system's retrieved context as the reference faithfulness = (# claims in answer supported by retrieved context) / (total claims in answer)
Why RAGAS uses an LLM as the judge rather than requiring labeled data: hand-labeling "is this chunk relevant" for every query in a large evaluation set doesn't scale. An LLM judge, prompted carefully, can assess relevance/faithfulness/entailment automatically across thousands of query-answer pairs — at the cost of inheriting whatever the judge model's own blind spots are (the same trade-off SS01 flagged for LLM-as-judge hallucination detection generally).
Section 05

Human Evaluation

Every automated metric above (BERTScore, RAGAS, LLM-as-judge) is ultimately validated against — and often initially calibrated against — human judgment. Human evaluation remains the ground truth other metrics are checked against, precisely because it's the only method that doesn't require deciding in advance what "correct" formally means.

Human eval methodHow it works
Direct ratingHuman raters score a response on a scale (e.g. 1-5) against defined criteria
Pairwise comparisonRaters choose which of two responses is better — often more reliable than absolute scoring, since relative judgments are easier to make consistently
Rubric-based annotationRaters check specific criteria (factual accuracy, tone, completeness) individually rather than giving one holistic score
Exam favourite: "If human evaluation is the gold standard, why not just always use it?" — cost and speed: human evaluation doesn't scale to the volume of continuous testing a production system needs (every deploy, every prompt change), and inter-rater disagreement is real even among careful humans. The practical pattern: use automated metrics (BERTScore, RAGAS) for continuous, high-volume checks, and periodic human evaluation to calibrate and validate that those automated metrics still track what actually matters.
Section 06

Key Takeaways & Exam Prep

✓

Hallucination detection needs an external reference

No method verifies truthfulness from generated text alone — every approach checks against something.

✓

Groundedness ≠ correctness

An answer can be true by coincidence and still ungrounded — that distinction matters for debugging RAG.

✓

BERTScore compares meaning, not surface tokens

Embedding similarity per token instead of exact n-gram overlap.

✓

RAGAS formalizes Module 3's evaluation layer

Automates faithfulness/relevance/context metrics via LLM-as-judge, no hand-labeling required.

✓

Human evaluation calibrates everything else

Automated metrics scale; human judgment validates that scaling didn't drift from what actually matters.

Common exam questions

QuestionShort answer
Why can't hallucination be detected from the generated text alone?There's no internal signal that distinguishes a true claim from a false one — every detection method needs an external reference (a knowledge source, other samples, an entailment model, or a judge) to check against
What's the key difference between BLEU/ROUGE and BERTScore?BLEU/ROUGE match exact n-grams and penalize valid paraphrasing; BERTScore compares contextual embedding similarity per token, so semantically equivalent but differently-worded text still scores well
What does RAGAS's faithfulness metric measure, and what does it map to?The fraction of claims in a generated answer that are actually supported by the retrieved context — the same concept as groundedness (SS02) and Module 3 §08's faithfulness, automated via LLM-as-judge
Why is human evaluation still necessary if automated metrics like RAGAS exist?Automated metrics need periodic validation against human judgment to confirm they still track what actually matters; human evaluation is the ground truth other methods are calibrated against, even though it doesn't scale to continuous, high-volume testing
